# 1A：1問のクイズを確認する

2026-09-11。1Aのローカル実装・自動検証・Edgeでの操作確認を実施。ユーザーが基本動作を確認済み。レビューで見つかった入力上限と再接続の問題も修正済み。1Bは未着手。

## 起動と操作

1. リポジトリで `pnpm dev` を実行する。既存の0A用設定を使い、新しい外部サービスは不要。
2. 起動ログに表示される開発originの `/game/` を開く。この環境では `https://desktop-149oae5.taildd84bf.ts.net:5173/game/`。
3. 表示名、未使用のルーム番号1〜16、人数2〜4、問題番号1〜12を入力する。
4. 別のブラウザーまたは独立したプライベートプロファイルから、同じルーム・人数・問題番号で参加する。同じブラウザーの別タブはcookieを共有するため同じactorになる。
5. 指定人数がWebSocket接続すると自動出題。早押しで本文が止まり、解答者本人だけに4択が表示される。
6. 文字を順に選ぶ。全文字正解で正解1、誤選択・文字期限切れでお手つき1となる。誤答者は同問に再解答できず、他の参加者が残っていれば本文を続ける。
7. 正解、全員ロック、全文表示後10秒の無buzzで1問を終了する。再試行は再読み込みし、別の未使用ルーム番号を使う。

ルーム14・15は初回画面検証、16はレビュー修正の接続上限検証に使用済み。追加確認には1〜13のうち未使用のルームを使う。登録・状態はローカルDOストレージに残る。1Aにはルーム再利用・待機取消UIを設けていない。

## 操作確認のシナリオ

- 2人で同時に早押しし、1人だけが解答できること。
- Tabで早押しボタンへ移動し、EnterまたはSpaceで操作する。パネル表示時は最初の選択肢へフォーカスが移り、Tabで移動できる。
- 意図的な誤選択、3秒の時間切れ、正解をそれぞれ試す。
- 他プレイヤーの文字パネルが見えないこと。
- 390px程度の狭幅と通常の画面幅で、文字・ボタン・フォーカスを確認する。
- 同じブラウザーで再読み込みして同じルームへ参加すると、cookieに対応したactorで現在のsnapshotと自分のパネルを取得する。パネルの期限は延長しない。ただし差分復帰・死活監視・人数不足の無効化は1Bで実装する。

## 実装範囲と制限

- `src/worker/game/`：ローカル参加認可、HTTP処理、DO、裁定、入力検証、サーバー専用問題。
- `src/client/features/game/`：接続hookと画面部品。`pages/GamePage.tsx`は組み立てのみ。
- `src/shared/game.ts`：公開snapshot・パネル・コマンドの型。正解・未表示本文のデータを置かない。
- 問題12問は日常・自然・科学等の一般的な事実を基に独自作成。本文・解説は既存問題集から転載していない。ユーザーが作問・デモ利用方針を承認済み。`questions.ts`の共通出典・許諾情報を全問に適用する。カタカナ読みを正答とし、ダミーは同ファイルの候補集合から重複なく3文字抽出し、正答と合わせて並べ替える。
- 1書記素100ms、1文字3000ms、判定2000ms、全文後10000ms。各出題の開始時に設定をDOへ保存する。NFKC→trim→書記素分割を使用。
- `now >= deadline`で時間切れ。現在パネルの絶対期限を保存し、コマンド処理時とAlarm時の両方で確認する。誤答後の全文後待ち時間は残り時間から再開する。
- 状態とコマンド応答を同一DO transactionへ保存し、その後でACK・snapshotを配信する。1問・参加者ごとに128コマンドまで保持し、超過は当該参加者だけ明示拒否。別の参加者の入力枠を消費しない。古い重複排除記録を消して再採点することはない。試合全体の保持方式は1Bで拡張する。
- 参加本文1024バイト、WSコマンド2048バイト、1接続毎秒20メッセージ、1actor最大3接続。最大16ルーム×4actor。正式な待機・運用上限は1C以降で定める。
- 開発参加は `import.meta.env.DEV` と `LOCAL_GAME_ENABLED=true` の両方を必要とする。Viteのserveだけで後者を設定。本番ビルドは変数を後からtrueにしても404。Origin確認、HttpOnly・SameSite=Strict cookieを使い、actorをコマンドの自己申告から決めない。
- 開発用cookieは1日。セッション失効後の参加枠回復やローカルデータ削除UIはこの段階の対象外。
- 1問終了を試合結果の確定として扱わない。7問先取・失格・問題枯渇・無効化・差分復帰は1B、正式認証は1C、DB保存と得点集計は1D。
- 1Aは現在状態を毎回snapshotで送る。roomSeqと同じパネルの復元は実装済みだが、G06/G07/G10の全ケース完了やクラウドHibernation確認を意味しない。

## レビュー修正後の接続動作

同じ参加者の接続は3タブまで。4つ目は参加APIで429 / CONNECTION_LIMITを返し、画面に他のタブを閉じる案内を表示する。参加APIとWebSocket接続の間に別のタブが接続して上限に達した場合も、WebSocket側で上限を再確認する。

WebSocketの確立または初回状態受信が10秒以内に完了しなければ接続を閉じる。失敗時は1.5秒後に再試行し、初回を含め5回連続で失敗したら自動再接続を止める。接続拒否コード1008の場合は直ちに停止。サーバー状態を受信したときだけ失敗回数をリセットする。「再接続」ボタンで新しく試行でき、未ACK入力は元のcommandIdで再送する。確立済み接続の死活監視は引き続き1Bの対象。
