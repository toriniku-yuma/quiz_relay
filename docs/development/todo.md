<a id="instance-top"></a>
## インスタンスのトップ・お知らせ・作問ルール

**`/` をインスタンスの入口とし、トップを正式なホームにします。** 別のホームやインフォメーション画面は作りません。更新・行動・説明・外部動線を1つの入口へまとめ、トップへ作問者向け情報や利用できない対戦を混ぜません。

### トップ

インスタンス未選択なら利用可能なインスタンス一覧、`/?instance=…` なら選択したインスタンスのトップを表示します。インスタンス切替でも対象のトップを開きます。主見出しはインスタンス名とし、運営組織名を補足表示します。

表示順は次のとおりです。

1. 最新のお知らせ3件
2. 利用可能な「ランクマッチ」「カジュアルマッチ」「部屋」の大きなボタン。利用できない対戦種別は理由を添えずに隠し、すべて利用できなければ「遊ぶ」の区分も隠す
3. 「インスタンスについて」。ルールと利用上の注意をまとめたMarkdown本文を省略せず表示し、末尾に外部参加へ共有できる現在のトップURLとコピーボタンを置く。URLはゲスト・未ログインを含む全閲覧者に表示する
4. 登録がある場合だけ「公式リンク」

公式リンクは組織管理者がHTTPS URL・表示名・短い説明・並び順を管理し、URLのホスト名から対応するブランドアイコンを選びます。対応のないサイトは共通の外部リンクアイコンにします。最大8件、表示名40文字、説明120文字、URL 2,048文字で、全項目を必須とします。新しいタブで開き、特定のサービスだけに登録先を制限しません。ロゴ・カバー画像は設けません。

未ログインのトップには、利用可能な参加方法として目立つボタンを置きます。メニューの先頭に「トップ」を置き、確認する流れは **トップ → ログイン → 待機 → 対戦 → 結果 → 再参加** とします。

### お知らせ

- 0件なら「お知らせはありません」と表示する。トップのタイトルから個別ページ、「すべて見る」から一覧へ移動する。
- 一覧は公開日時の新しい順に10件ずつ表示する。個別ページはタイトル・公開日・Markdown本文を表示する。
- 公開日時は初回公開時刻を保持し、画面には日付だけを表示する。審査結果や処分など個人宛のサイト内通知とは分ける。
- 一般利用者には公開内容だけを返し、非公開のお知らせの直接URLを表示しない。

### 管理

組織管理者はインスタンス設定から「トップページ管理」を開きます。管理トップに「インスタンスについて」と公式リンクの編集欄、お知らせ一覧を置き、お知らせの新規作成と1件ごとの編集は専用ページへ分けます。

- お知らせはタイトルと本文を必須とし、「非公開で保存」と「保存して公開」を選べる。予約公開と専用の下書き状態は設けない。
- 公開中の編集は保存と同時に反映し、公開・非公開は即時に切り替える。現在非公開のお知らせは、公開履歴の有無にかかわらず簡易確認後に削除できる。
- 編集とプレビューを切り替えられる。未保存内容はインスタンス・入力者・編集対象ごとにブラウザーへ自動保存し、再訪時に自動復元して通知する。保存・削除の成功時に消し、「保存済みの内容に戻す」で破棄できる。別端末へは同期しない。
- 版番号が変わった同時編集は上書きせず、入力を残して競合を知らせる。自動マージは行わない。

### Markdownと文字数

標準Markdownで記述し、HTMLを実行しません。見出し・段落・箇条書き・引用・強調・コード・リンクと、HTTPSの外部画像を表示できます。画像は空でない代替テキストを必須とし、HTTP・`data:`・SVGを拒否します。画像は遅延読込して表示幅を制限し、外部リンクは別タブで開きます。

お知らせタイトルは100文字、「インスタンスについて」・お知らせ本文・作問ルールは各20,000文字までとし、空白だけの必須値を認めません。画面とAPIの両方で制限します。

### 作問ルール

新規作成・編集・JSON取込の各ページのフォーム上部に「作問ルール」を置き、選んだときだけMarkdown本文を開きます。初期状態では閉じ、対象インスタンス名も表示します。トップには表示しません。

作問ルールはインスタンスごとに管理し、組織管理者が既存の「投稿設定」で編集します。Markdownの編集・プレビュー、外部画像とリンクの条件はトップと共通です。読込・再試行・開閉で入力中の問題や取込内容を失わず、他インスタンスのルールを表示しません。取得失敗時だけ再試行を表示します。

### 公開条件

「インスタンスについて」と作問ルールは、インスタンスの新規公開条件です。既存の公開インスタンスは公開状態を維持しますが、次回のインスタンス設定保存または再公開から両方の登録を必須とし、サーバーでも拒否します。準備中のインスタンスで未登録ならトップに「未登録です」と表示します。お知らせと公式リンクは公開条件に含めません。

### 完了条件と検証

対象インスタンスと組織管理者権限をサーバーでも確認し、他インスタンスの内容を混ぜません。取得中は回転表示、未登録・取得失敗を区別し、失敗時だけ再試行を表示します。閲覧・画面移動中も、参加処理・待機・部屋ロビー・試合との接続を維持します。

自動試験とPC・スマートフォンの画面確認で次を検証します。

| 項目 | 合格条件 |
| --- | --- |
| 入口とURL | `/` は未選択なら一覧、`?instance=…` なら対象トップ。切替後もトップを開き、ランクは `/rank/`。別ホーム・別一覧ルートがない |
| トップ | 組織・インスタンス名、最新3件、利用可能な対戦だけ、「インスタンスについて」の全文、共有URL、登録済み公式リンクを順に表示。空・読込中・失敗を区別する |
| お知らせ | 公開済みだけを新しい順に返し、トップ3件・10件ずつの一覧・個別ページで同じ内容を表示。非公開の直接URL、別インスタンス、ページ境界で混ざらない |
| 管理 | 組織管理者だけが対象インスタンスを更新。必須・文字数・Markdown・画像・公式リンクを検証し、即時公開・非公開・非公開削除・版競合を正しく扱う |
| 編集内容 | 編集とプレビューを切り替えても入力を保持。ブラウザー内の未保存内容を対象別に自動復元し、保存・削除・破棄で消す。別利用者・別インスタンスへ復元しない |
| 公開条件 | 新規公開は常設本文と作問ルールが必須。既存公開先は状態を維持し、次回設定保存・再公開から拒否。お知らせ・公式リンクは必須にしない |
| 作問ルール | 投稿設定の保存内容を新規作成・編集・JSON取込で開閉表示し、トップには出さない。取得・再試行・インスタンス切替で問題や取込の入力を失わない |
| 接続維持 | トップ・一覧・個別・管理への移動とインスタンス切替で、参加処理・待機・ロビー・開始済み試合を取り消さず、元の参加先へ戻れる |

## URL構成の変更

**ランク参加を `/rank/` へ移し、設定類を用途別のパスへ分けます。** トップの実装と同時に行います。

| 用途 | 変更後のパス |
| --- | --- |
| インスタンス一覧・トップ | `/`・`/?instance=…` |
| ランクマッチ | `/rank/` |
| 組織設定 | `/organization-settings/` |
| インスタンス設定 | `/instance-settings/` |
| 運営終了・再開 | `/instance-closure/` |
| 完全削除 | `/instance-deletion/` |

- 開発参加は `/local-game/`、技術検証は `/debug/` のまま。`/game/` の転送や、別のホーム・`/top/`・`/information/`・`/instances/` は設けない。
- 設定類をランク画面の表示切替へ同居させない。
- ログアウトまたはセッション切れで非ログイン状態になったら、現在の履歴を置き換えて `/` のトップへ移動する。
- 外部参加では、開催先の `/?instance=UUID`（または `/rank/`・`/casual/`・`/rooms/`）を入力する。トップURLは対象1件の組織・インスタンス名・参加できる対戦種別を表示し、そこから参加方法を選べる。
- `/rank/?instance=…`・`/casual/?instance=…`・`/rooms/?instance=…` は指定先を開く。

## 正解の読みを1問1種類に統一

**正解は1問につき「表示用正答＋入力用ひらがな読み」の1組だけにします。** 異なる読みや表記揺れを別の正解として追加する操作・データ形式を設けません。作問・改訂・JSON入出力・部屋の持込問題のUI修正時に行います。

- 読みは1〜20文字。文字数は見た目の1文字（書記素）で数える。長音・小書きは許可するが、表記揺れを別の正解読みとして登録しない。
- 登録した読みの全文に到達した時点だけを正解とする。
- 文字パネルは常に4択で、正しい次文字を含め、残りをひっかけ・ダミーで埋める。
- 正解の読みとひっかけを照合し、回答が続く各入力位置の候補が4択に収まることを確認する。収まらない場合は該当する入力位置と理由を表示し、修正を促す。候補を自動で削除しない。
- 持込問題も通常問題と同じく、表示用正答と入力用読みを各1件だけ登録する。
- 作問・改訂・JSON入出力で、異なる読みや表記揺れを別の正解として追加できないことを検証する。
