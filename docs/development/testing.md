# 開発側の検証項目

[ドキュメント一覧](../README.md)

変更した機能に関係する項目を選んでください。確認済みの範囲と受入条件をまとめています。実行ごとの日時・Worker版・計測値・使用量はGit管理外の検証出力と会話で扱います。

<a id="d1-clerk"></a>
## D1・Clerkの検証

通常アプリ・ローカル開発・管理CLI・非公開消去Worker・定期処理はD1、認証はClerkのGoogleログインを使います。

| 検証対象 | 確認済みの範囲 |
| --- | --- |
| 全体検査 | `pnpm run check` によるBiome・型検査・自動テスト・監視ツールのテスト・設定とseedの検査・ビルド。組織単位の参加、受入2方式、相手組織ごとの対戦種別制限、明示禁止、本人履歴と振り返り、古いキャッシュより新しい拒否の優先、作問者名変更の再同期を確認。外部ログインのstate・本人・用途・再利用の検証、ログインだけでは参加しないこと、開催先だけの終了、URL除去中の交換処理の継続、期限切れ要求の再送防止も確認。監視の起動失敗・予定外終了・バッファ上限超過も失敗として判定 |
| D1の整合性 | 組織・権限・運営・作問・審査・部屋・結果・難易度・退会・期限処理。atomic batchのrollback、競合時の再計画、不変版・原本の改変拒否、100件の問題一覧と1,001行の処理 |
| Clerk | 実SDKの署名・issuer・origin・期限・Google連携の検証。別鍵・別origin・azp欠落の拒否、遅い応答・トークン更新・通信障害からの復旧 |
| ローカルChrome | 実Googleログイン、待機参加、画面移動中の接続維持と取消 |
| 実DOからD1 | 通常対戦の保存・本人履歴・順位、再保存での二重加算防止、未出題問題・第三者への非公開 |
| 退会・削除 | 隔離D1・実DO・非公開service bindingで即時拒否、Auth障害と再試行、匿名化、再登録時の権限分離、完全削除・期限消去・復元後の再消去。24問の結果匿名化で計算の重複を減らし、DB側でも同じ処理を使用。得点の改変は引き続き拒否。実アカウントは削除していない |

テストは固定の本人確認fixtureを使い、実Clerkの秘密を引き継ぎません。`vitest.config.ts` は `wrangler.jsonc` からWorkerの構成だけを読み、値は同ファイルで明示したbindingだけを使います。開発者の `.dev.vars` は読み込みません。実D1・DO・署名通信と、本人確認fixtureを区別します。全体試験の同時実行は4ファイル、各テストの上限は20秒です。大量データ試験の所要時間を保ち、通常時の5秒制限による環境依存の失敗を避けます。

### インスタンス間連携

無料の公開A/Bに、通常ゲームWorker、同じD1・DOへ接続する非公開消去Worker、毎分Cron、別々のClerk Developmentアプリと署名鍵を配置しています。各側に1組織・2インスタンスを用意し、実Googleユーザーを検証管理者に登録しています。[構成と再配置](../guides/setup.md#federation-test)を参照してください。

| 層 | 確認済みの範囲 |
| --- | --- |
| 実ネットワーク | A/B双方向の署名、nonce再送拒否、不正署名・宛先・期限・Originの拒否、停止・転送・応答遅延・復旧 |
| 現在の公開ゲームAPI | `federation:check:cloud` の14項目でA/Bの設定・管理画面の直接表示・本人確認設定・未認証拒否・同期鮮度・双方向署名・再送/不正要求拒否・問題取得を検査。実Cronと非公開serviceの成功、共有同期の一時通信エラーから定期再試行による復旧を観測。メタデータ同期を保守DOへ移した後に、手動同期なしで更新時刻が進み、定期処理が成功することを確認。単発成功や短時間の監視は継続安定性や対戦全体の受入を保証しない |
| 実Google・公開Chrome | A/B通常画面のログインと本人確認、外部ランクと部屋対戦、結果保存、所属元の外部履歴と開催元の出題済み振り返り。別Googleアカウントの一般参加者による外部ランクの開始、再読込後の同じ本人・試合への復帰、終了・保存確定・所属元の本人履歴を確認。所属元だけ未承認の場合も同じ範囲を確認。単独タブの待機は最後の接続切れで取消し、理由表示を確認。同じ本人の待機2タブでは片方の再読込後も待機を復元。URLからA-1を開き、お気に入り追加と一覧・切替メニュー、再読込後の参加リンクの自動表示も確認 |
| 参加の自動回帰 | ランク・カジュアル・部屋の一度限りチケット、最大2枠、応答不明・取消・再接続・ログアウト・期限清掃、開始済み試合と次試合の認可の区別。所属元未承認・明示禁止・開催元未承認の境界と、初回鍵取得時の転送・サイズ・URL制限も検査 |
| 定期保守の自動回帰 | Cron本体の完了待機、一時中断時の新しいstubでの限定再試行、過負荷・業務エラーの即時再試行拒否、再試行失敗の伝播。監視の予定時刻・処理段階記録と秘密情報の除外も検査 |
| 外部部屋の実D1・DO | 作成・再送・二重作成拒否、別参加者の入室、非公開WebSocket、所属元の制限変更後の準備拒否、開始・子試合・結果配送・親ロビーへの復帰 |
| 問題共有の自動回帰 | インスタンス単位の許諾・停止・改訂、25件ずつの固定snapshot、固定3区分・補正保持、個別除外の維持、横断検索・出典・共有キャッシュ期限、一般ユーザーへの原本非公開 |
| 管理UIの公開Chrome | 組織名、受入2方式、相手組織の承認、ランクとカジュアル／部屋の個別制限、明示禁止の保存と再読込。確認後の元の設定への復元 |
| 問題共有の公開Chrome | A/Bのインスタンス単位の送受信許可、BからAの取り込み範囲・保存先の変更と自動反映、横断検索、個別除外と解除、難易度の固定と復元 |
| 配送の自動回帰 | 結果の不変署名原本、重複成功・別hashの隔離、429と永続再試行、開催元別レート、匿名化・完全削除イベント、削除直後の利用停止と遅延配送。未承認先からは本人の参加記録に一致する結果だけを受理し、別actor・instance・matchと無関係な制御通知を拒否。開催後の許可削除で本人の結果配送を失わない。保存直後の配送が失敗しても永続送信記録を保持し、再試行後に本人履歴へ一度だけ反映 |
| スマートフォン表示 | Chromeで360px幅の外部部屋ロビーを確認。ページ全体は横にはみ出さず、参加者表だけ内部で横スクロールする |

仮想利用者による4人ランクと8回答者＋専任者1人の部屋の30分継続試験は合格しています。入力再送の裁定、同じ試合への再接続、結果保存、所属元の本人履歴への反映、親ロビーへの復帰を確認しました。所属元だけ未承認にした構成での参加と本人履歴への配送も検証しています。外部ログインのUI変更後には、長時間負荷試験を再実行していません。[実行方法と使用量の取得](../guides/setup.md#federation-load)を参照してください。

公開Chromeでは、所属元リンクから再読込なしの自動ログイン、開催先会員の優先、共通メニューの表示名・所属、開催先だけのログアウトと再読込後のゲスト維持、所属元ログインの維持を確認しています。ランクの接続・待機取消、単独タブの待機解除、部屋一覧・作成フォーム、期限切れ要求の開催先への復帰案内も確認済みです。UI変更後の外部部屋作成では、本人確認の往復後に同じ設定で作成し、開催先の会員ログイン入口から元の部屋へ戻って別アカウントで入室できました。準備・開始・文字回答と正解判定・指定問題数での終了・保存確定・所属元履歴・開催元の振り返り・親ロビー復帰も確認しています。問題数表示と、閉じた部屋の再接続停止・退出・保存済み復帰情報の解除は、修正後にChromeで確認しています。

非公開の外部部屋は、実アカウントのChrome操作と仮想参加者を組み合わせ、招待入室・部屋主交代・持込問題とパスワードの保存・招待URL再発行を確認しています。古い招待と誤ったパスワードを拒否し、入力を訂正して入室できること、正解判定・終了・保存確定・所属元履歴・開催元の振り返り・親ロビー復帰と次試合も確認しました。閉鎖成功後は再取得による誤ったエラーを表示せず、閉鎖状態から退出できます。

### 残る受入確認

| 対象 | 残る確認 |
| --- | --- |
| 接続と同期の継続安定性 | 待機接続の切断は復帰できたが、直接原因の特定は未完了。監視を試験開始前に確立して調べる。一時的な問題同期の競合は定期再試行で復旧しており、発生頻度を確認する。保守Cronには完了待機と一時中断時の限定再試行を追加し、短時間の同期継続を確認したが、過去に観測したキャンセルの直接原因は未特定。参加要求の通信失敗についても応答待ち超過か相手側エラーかの原因を確認する |
| UI変更後の負荷 | 通常の参加・再接続・保存・履歴配送を長時間試験で再確認。過去の30分試験の合格を、変更後の受入完了として扱わない |
| 実機・退会 | iOS Safariの認証・戻る操作・背景移行・回線切替。本人による実Googleアカウントの退会・再登録 |
| 本番配置 | Clerk Production・独自Google OAuth・独自ドメインの準備 |

[公開A/Bの自動検査](../guides/setup.md#federation-cloud-check)は、画面操作と実機の受入を代替しません。

### 外部連携のUI確認

公開A/Bか、migration適用済みのローカル環境で確認します。一般参加者の操作と管理者の設定を分け、制限変更は検証環境だけで行い、確認後に元の設定へ戻してください。参加方式・相手組織の設定は組織全体に適用されます。

| 画面・変更点 | 操作 | 確認する結果 |
| --- | --- | --- |
| インスタンス一覧 `/game/` | 外部欄を開き、URLを入力。お気に入りを追加・解除して再読込。承認済み一覧を展開し、接続先を切り替える | 参加元欄・通常の「一覧を再取得」・「相手の情報を更新」はない。接続先の切替だけで取得し、選んだ相手のインスタンスを表示。お気に入りが保持され、登録だけでは参加しない。承認済み一覧は必要時だけ表示 |
| 外部先の詳細 `/external/` | お気に入りかURLから開く。再読込する | 名前・組織・許可された種別のリンクが表示され、参加元の選択はない。利用不可のお気に入りも情報を再確認できる |
| 取得エラー | 無効なURLを入力する。検証時だけ通信を遮断し、復旧後に再試行 | エラー時だけ「再試行」が表示される。古い許可を使って参加させず、お気に入りを消さない |
| 組織設定 `/game/?view=organization` | 組織名を変更して保存・再読込。インスタンス一覧から個別設定を開く | 組織名を保持し、本人識別・権限・戦績は変わらない。一覧は状態と個別設定への入口で、個別設定フォームを重複表示しない |
| ユーザー管理 `/users/` | 組織管理メニューから開き、処分・権限・通報のポップアップで対象を切り替える | 管理者は全体を集計し、担当モデレーターは担当範囲だけ。対象の最新情報を取得し、遅れた別対象の応答を使わない。保存中・応答不明中は対象を変更できない。全体BANは管理者だけ |
| 外部組織との連携 `/federation/` | 組織管理から「外部組織からの参加」で2方式を切替・保存・再読込 | 初期値は承認済みのみ。保存した方式を保持。「禁止先以外」の方式では未承認でも参加できる。問題共有は自動許可されない。インスタンス設定は同じ画面へ混在しない |
| 相手組織の承認と参加制限 | 承認後にランクだけ外して保存。カジュアル／部屋、明示禁止も個別に切替 | 承認直後は両種別を許可。ランク制限はカジュアル／部屋へ波及しない。明示禁止は両方式で優先し、新規参加を拒否。承認解除だけでは明示禁止にならない |
| 自動ログインと通常画面 | 所属元の詳細から「開催先のランク／カジュアル／部屋を開く」。所属元でログイン済みならボタンを押さずに戻る。開催先URLだけを別に直接開く | 新しい入口は通常の `/game/`・`/casual/`・`/rooms/` に戻り、自動本人確認する。表示名・所属元が共通メニューに出る。閲覧だけで待機せず、直接URLだけでは所属元を推測しない |
| 開催先の会員ログイン | 開催先自身のアカウントでログイン済みのまま所属元リンクを開く。外部ログイン中はアカウントメニューの「この組織のアカウントでログイン・登録」を確認 | 開催先会員を優先し、外部ログインだけでClerk会員登録しない。会員ログイン後は元の通常画面・instanceへ戻る |
| 開催先だけのログアウト | 外部ログインで「ログアウト」し、再読込。別タブの所属元も再読込し、再度所属元リンクを開く | 開催先はゲストを維持して勝手に再ログインしない。所属元はログイン済みのまま。所属元リンクを開き直せば再ログインできる |
| 外部の部屋入口 | 通常の部屋画面で一覧・出題設定を開き、部屋作成／入室を選ぶ | 一覧だけでは参加枠を取らず、作成／入室で自動本人確認して同じ部屋操作に戻る。再送で別部屋を作らない。問題数方式の対戦画面には実際に出題する上限を表示する |
| 部屋の閉鎖と退出 | 部屋主がロビーで閉じる。参加者が退出し、閉じた部屋の保存済み復帰情報でも再読込する | 閉じた部屋には再接続せず、接続待ち・通信復旧エラーを表示しない。閉鎖後の退出は終了済み参加のAPI拒否で止まらない。利用できない保存済みの部屋は復帰対象から外す |
| 待機・対戦・履歴 | 参加後に待機中／対戦中の再読込、終了後に通常の「対戦履歴」を開く。開催元の振り返りも開く | ランク／カジュアルの待機は最後の接続切れで解除し、外部ログインは保持。他タブが接続中の待機・開始済みの試合は同じ参加へ復帰。通常の履歴入口にも自分の外部結果を1件だけ表示し、自組織の結果と並べて読める。所属元レートには加算しない |
| 参加要求の期限切れ | 通信失敗後、参加要求の60秒期限を過ぎて再試行 | 期限切れの理由と「開催先に戻る」を表示。同じ終了済み要求を再送せず、開催先の参加ボタンから新しい要求を始める |
| インスタンスごとの共有許可 | 個別インスタンスの「問題共有・結果配送」で接続先を切り替える。検証環境で取得失敗後に再試行する | 接続先の切替だけで相手のインスタンスを取得。通常の取得ボタンはなく、失敗時だけ再試行を表示。問題の送出・受入の設定と結果配送の状況を表示する。外部対戦のランク／カジュアル許可は組織管理の相手組織側の欄で設定する |
| 問題カテゴリの割当 | 「問題管理 → 共有問題」で受け取り元を追加し、全カテゴリ／選択カテゴリと保存先を選ぶ。A→X、B→Y、複数元→Xを確認 | 複数の取り込み専用カテゴリを作れる。通常の作問・JSON取込・問題移動では保存先に選べず、APIでも拒否する。候補は自動表示し、相手APIをクリックのたびに呼ばない |
| 共有問題の検索・除外 | 「全問題」で種類・共有元を絞り込み、通常問題と検索する。問題の操作で除外・解除し、自動更新後も確認 | 専用の検索画面・手動同期ボタンはない。除外が更新で復活せず、本文・出題済みの過去版は保持する。難易度は簡単・普通・難しいの3区分 |
| 公開鍵の入手 | 組織設定で接続先URLを入力し「相手を確認」、内容を確認して承認・保存する | 鍵の手入力欄はない。HTTPS・固定path・サイズ・時間・redirectの制限で自動取得し、承認・既存鍵の置換は勝手に行わない。鍵更新は管理者が確認・保存する |

Chromeでは通常の画面操作を自動化できます。人による確認では用語・説明・操作感と、iOS Safari実機の認証・戻る操作・背景移行からの復帰を優先します。本人による退会・再登録は引き続き本人が担当します。インスタンスのトップ・お知らせ・作問ルール掲示は今回作成せず、URLの入手・共有方法も後続の作成時に追加します。

### クラウドの画面受入と実機確認

下表は受入条件の一覧です。完了した部分は上表に記載し、残る条件と区別します。Chromeの通常操作で確認できる項目はブラウザー自動操作で進めます。複数利用者・権限の試験では、別のGoogleアカウントと独立したログイン環境を用意し、一般参加者と管理者を分けます。アカウントを分けることと、人が全操作を行うことは別です。Googleの追加本人確認は本人が対応し、Googleアカウントは自動生成しません。退会は本人が行います。既存管理者を削除試験に使わず、退会用の別アカウントを用意してください。

| 項目 | 手順 | 合格条件 | 確認方法 |
| --- | --- | --- | --- |

## モデレーションと対戦休止の受入

- 個人処分・サーバー全体休止・外部全体／特定所属元の受入を画面と認可で区別する。
- 専用パーミッションの有無、管理者／運営者への操作境界、本人への理由表示とサイト内通知、非公開の運営履歴を確認する。
- タイムアウトの期限前後・早期解除とBAN／部分制限の手動解除を確認し、一つの解除で別の有効な処分が消えないことを確認する。
- 対戦機能の個別停止は一般ユーザーの新規参加・開始を拒否し、組織管理者・対象インスタンスの管理権限を持つモデレーターは通常参加・待機・開始できる。他インスタンスだけの権限では参加できず、他の対戦種別・作問には影響させない。
- インスタンス全体休止（準備中）は一般ユーザーの新規対戦・作問を拒否し、対象の管理権限者は通常機能を利用できる。他インスタンスだけの権限では利用できない。
- いずれの停止も開始済み試合・再接続・結果保存を維持する。再公開しても個別停止を解除せず、権限と公開状態をAPI直接アクセスでも検証する。
- 外部全体禁止と先別許可、外部許可と個人BAN、自サーバー所属者と外部受入設定の組合せを確認する。所属のないゲストを自サーバー所属と誤認しない。
- 個人処分は次試合から適用し、既存試合の継続・再接続を妨げないことを確認する。ゲスト回避時はゲスト受入を閉じられる。基本的な識別・再接続は別途確認する。処分や包括的制限の変更で過去レートを自動取消しない。

## 組織・インスタンスの分離

組織内で管理者・ユーザーを共有し、配下インスタンスでモデレーター・問題・レート・待機列・部屋を分ける方向を計画へ反映する。

同組織内と別組織間の両方で、インスタンス別の認可を確認します。

受入の追加対象は、管理画面からのインスタンス追加（別DB/Auth構築・追加デプロイ不要）、同一アカウントでの複数インスタンス利用、インスタンスを跨ぐ権限・問題管理・レート・待機列・部屋の混入防止、対象インスタンスを示す画面導線。

同組織内の共通ユーザーにはインスタンス間の外部参加許可を要求しないこと、別組織への参加は開催元の受入方式・相手組織の種別許可と所属元の明示禁止で制御すること、問題共有は同組織内でもインスタンスごとの設定に従うことと、一括設定操作が選択対象以外・後から追加されたインスタンスへ波及しないことを追加受入とする。

機能ごとの実装と画面受入は[計画](plan.md)に従います。

## 外部インスタンスのお気に入りの受入

[組織間連携の仕様](../spec/federation.md#外部インスタンスをお気に入りに追加する)の実装時に確認します。自組織内のお気に入りの実装検証とは別です。

- インスタンス一覧でURL取得先・お気に入り・承認済みの利用可能な外部先を確認し、本人の操作で個別に追加・解除できる。発見一覧とお気に入りだけの切替メニューを区別し、接続先の承認・新規作成・直接URLで自動追加しない。
- 所属アカウント別に保存し、別端末でも同じ登録を読み込む。同じ先の再追加は重複せず、同名・同じinstanceIdの別組織や別アカウントの登録を混同しない。
- お気に入りの追加で管理者の承認・参加許可・参加枠・本人認証を変更しない。未追加の直接URLも既存の認可に従い、お気に入り経由でも本人の所属組織・対戦種別・開催元の受入方式と組織別許可、所属元の明示禁止と個人制限を確認する。
- 明示禁止・停止・許可取消を最新情報で確認した先を切替メニューから隠し、本人の登録と解除操作を保持する。再許可で表示が戻り、通信失敗を登録削除の理由にしない。
- 追加・解除・閲覧先変更・画面移動で参加処理・自動待機・部屋ロビー・開始済み試合の接続を中断しない。管理者の接続先管理と非ログイン時のゲスト参加導線を維持する。

## 引継ぎ・退会・共有の受入

- 管理者引継ぎは後任承諾前に現管理者を失わず、承諾後に指定した権限状態になる。
- 完全削除は管理者のみが対象名を一致させてSubmitした場合に実行し、不一致・別対象・無権限では実行しない。消去範囲は[組織の削除仕様](../spec/organization.md)に従う。
- 共有解除・取得エラーになった共有元の問題を新規出題に使わず、進行中の固定内容を変更しない。
- 作問・改訂・JSON入出力のUI修正時に、表示用正答と入力用読みを各1件だけ扱い、異なる読みや表記揺れを別の正解として追加できないことを確認する。対戦ではその読みの全文に到達した時点だけを正解とする。
- 退会の通常非表示・相手結果と必要な調査記録保持は承認済み。退会者のアカウント利用拒否、通常プロフィールとランキングからの非表示、相手履歴の「退会ユーザー」表示、相手の勝敗・レート維持、運営の権限内閲覧を確認する。

  保持項目・期間は別途確定する。

## アカウント単位の同時参加

自動待機・部屋ロビー・回答者・出題専任の組合せで、同じアカウントの参加枠を最大2つに制限し、新参加の成立後に前の本人だけを離脱させることを確認します。別組織の参加・取消・枠の回収はD1と実DOの連携試験で確認します。
複数タブ・同時要求・取消と再参加・通信の応答消失で旧参加を復活させません。候補登録と画面移動だけでは自動待機・部屋ロビー・開始済み試合を解除しません。最後の接続切れで自動待機を除外し、別タブが接続中なら保持します。取消時点で開始済みなら試合と30秒の復帰猶予を維持します。

## 表示名・引継ぎ

- 同一組織で表示名の重複と同時登録・変更競合を拒否し、別組織の同名は別人として扱う。名前変更の回数制限を設けず、現在プロフィール・ランキングだけが即時更新され、待機・対戦・過去結果と不変IDは変わらない。
- 管理者招待の7日間の期限、取消、承諾時の再認可、旧管理者の権限を残す／外す選択を検証する。全管理者のアカウント喪失時は、設置者のサーバー側復旧と監査を確認する。

## 審査なし方式への切替

審査中の新規投稿・改訂が、取下げ・再提出・個別承認なしで審査を通ることを確認します。使用停止・形式検証を維持し、未提出の下書きを公開せず、進行中の試合・過去結果を変更しません。

## 作問者資格

- 同じインスタンスの申請中は1件とし、他インスタンスの資格を投稿許可に使わない。
- 不承認理由と再申請可能日時を本人へ表示し、管理者設定の待機期間内は再申請を拒否、満了後は受け付ける。
- 資格管理担当だけが承認・不承認・直接付与・取消を操作でき、直接付与で申請中の申請も承認済みになる。
- 取消で審査中・差戻し中の審査を終了して下書きを残し、公開済み・使用停止中の状態を変えない。再付与で終了した審査を再開しない。
- 承認作問者限定方式では取消後の提出を拒否する。一般投稿方式では資格取消だけで投稿を禁止せず、個人の投稿制限を別途適用する。

## 新設計の受入検証

| 対象 | 確認する境界 |
| --- | --- |
| 申請・開始の競合 | 取下げ後の承認拒否、待機中の問題停止・設定変更後も固定版で開始、開始済み固定版の維持 |
| JSON | 500問／501問、2,000,000／2,000,001バイト、分割時の欠落・重複なし、不正1問で全件未取込、同じ再送で二重下書きなし |
| 組織間通信 | 期限切れ・別宛先・改ざん・重複交換・ポップアップ拒否・再送・鍵更新・独自ドメインの実接続とSSRF境界 |
| 部屋 | 8回答者＋専任1人、途中参加はロビー、保存待ちで次試合へ進んでも原本保持、空室閉鎖・切断復帰 |
| 復元と匿名化 | 日次バックアップ・DO未保存結果を復元し、削除済みデータが復活せず、再送で結果・レートを二重反映しない |

性能試験は同地域でランク4回答者と部屋8回答者＋専任者をそれぞれ1室30分稼働し、クライアント送信からACKまでp95が500ms以内を初期目標とします。条件・サンプル数・結果を記録し、未測定値を保証として表示しません。通常の多室同時稼働も上限設定に沿って検証し、16回答者は後続です。既存の許可範囲で実施し、有料契約を自動追加しません。
