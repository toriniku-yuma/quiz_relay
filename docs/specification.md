# MVP仕様

## 目的と範囲（企画要件）

問題文が徐々に表示され、早押しで解答権を得るマルチ対戦を提供する。名称、素材、画面は独自制作する。各運営者は独立した管理者、DB、Auth、署名鍵を持ち、問題セット・レギュレーション・連合先を選べる。水平スケール用の複数サーバーとは異なる。

プレイヤーは所属元でログインし、他インスタンスのルームへ参加し、戦績を見る。管理者は問題・ルールの版管理、peer承認、結果除外を行う。問題作成者は本文・許容解答・解説・出典・許諾を登録する。管理操作は所有者と権限を検証する。

MVPは2〜4人、10問、1ルールを出発点とする。独立したA（Web技術）とB（別コミュニティ）を構築し、B所属プレイヤーがAの共通大会で対戦し、両方で同じ順位を確認する。単体対戦だけでは完了しない。

## ログインとマッチング（2026-09-07回答反映）

所属元でメールのマジックリンクとSNSアカウント認証を提供する。MVPのSNS認証はGoogleとする。所属actorの識別はログイン方式によらずhomeOriginとAuth subjectを使い、表示名やSNS名で成績を統合しない。

自動マッチングが完了したら、管理者の開始操作や追加の準備完了操作を待たずに開始する。開始に必要な接続・参加認証・固定問題とルールの準備までをマッチング完了に含める。同じ開催元・大会・ルール版・設定人数の待機列で組み合わせ、設定人数がそろったら開始する。人数は変更可能とし、初期人数は指定がないため2人を仮置きする。MVPの設定範囲は2〜4人を提案する。待機中の取消と同一actorの重複参加防止を用意する。

開始後の新規参加は認めず、切断者の参加記録は保持する。試合中に開催元が接続中のactorを1人以下と判定した時点で、再接続猶予を設けず即座に無効試合とする。0人も対象。同じactorの複数接続は1人と数える。待機中には適用せず、FINISHED後の切断でも無効化しない。無効試合は勝数・総得点・参加数のすべてから除外し、終了理由を表示する。

## フロントエンド構成

React + TypeScript + Tailwind CSSを採用し、Viteでビルドする。画面や繰り返すパーツはReactコンポーネントとして実装する。紹介SPAとは独立したゲームアプリケーションにする。[実装方針](development.md)と[採用判断](adr/0003-tailwind-css.md)を参照。

## 画面

| 画面 | 必須情報・操作 |
| --- | --- |
| ホーム | 運営方針、開催ルーム、ルール、承認peer、所属ログイン |
| マッチング・ロビー | 開催元、大会、参加人数、固定ルール版、問題セット方針、参加・待機取消。マッチング完了後に自動開始 |
| 対戦 | 表示済み本文、大きな早押し操作、解答権保持者、締切、各参加者の得点、解答者本人のカタカナ選択パネル |
| 結果 | 各問の正誤と得点、保存中／確定、ランキング反映状況 |
| ランキング | ローカル／連合、大会、期間、ルール版、勝数・総得点・参加数、最終同期時刻 |
| 管理 | 問題改訂、許諾、ルール新規版、peerと鍵承認、結果除外、隔離・再送状況 |

クイズを画面の主役にする。インスタンス情報と同期状態は参加条件や結果の信頼性に関わる場所に出し、内部ログは管理画面へ置く。接続断・再接続中は操作状態を明示する。タッチとキーボード操作、フォーカス、色以外の正誤表示に対応する。開催地域の表示方法は実測可能性を検証し、RTTを表示する。DOの配置指定を厳密な開催地域保証と表示しない。

## レギュレーション

任意コードは実行せず、サーバー検証可能な宣言的設定とする。AI採点・曖昧一致は対象外。

| 分類 | 設定 |
| --- | --- |
| 出題 | ジャンル、問題セット版、問題数、文字表示速度 |
| 解答 | 制限時間、Unicode正規化方式、前後空白除去、許容解答一覧 |
| 採点 | 正解加点、誤答減点、当該問題の再解答ロック |
| 終了 | 規定問題数、目標点、同点処理 |

例示値は10問・正解+10点・誤答-5点・解答時間10秒。実績ではない。減点は `incorrectPenalty: 5` のような非負の量を設定し採点で引く提案とする。負数禁止を最終得点に誤適用しない。整数、有限値、上下限、文字数、列挙値を検証し、各上限は実装前に確定する。

開始時に `rulesetId / version / rulesHash / questionSetVersion / scoringVersion` と使用問題の `questionId / questionVersion` を固定する。編集は新しい版を発行し、進行中の試合や過去結果に遡及しない。

### カタカナ選択式解答

解答権保持者が、1文字分ずつ表示されるカタカナ選択パネルから文字を選ぶ。各パネルに正解候補と引っ掛け用の候補を用意する。自由入力はMVPに含めない。初期値は正解1個＋ダミー3個の4択。誤選択した時点で誤答とし、減点・当該問題ロックを行う。制限時間は解答権取得から解答全体で10秒とし、文字選択やパネル更新で延長しない。選択肢数と制限時間は調整可能にする。

問題データには表示用の正答と、パネル用のカタカナ読みを分離して登録する。NFKC→trimの後に書記素単位へ分割し、サーバーで完全一致判定する。NFKCだけではひらがなからカタカナへの変換は行われないため、パネル用読みはカタカナとして登録・検証する。長音・小書き文字を許容し、表記揺れは明示した許容読みとして扱う。MVPのモックは1問につきパネル用読み1通りから始め、複数読みを使う場合の候補分岐は別途契約を確定する。

正答位置、正答全文、将来のパネルはクライアントへ先送りしない。サーバーが当該文字の候補を生成し、解答者本人だけへ送る。候補に含まれる文字と正答そのものの先行公開を区別する。

### 調整可能な設定

数値は実装に散在させず、初期設定を1か所で定義する。実行時の正はDBの版付き設定とし、定数は新しい設定を作成するときの初期値に使う。UIは試合に固定された設定を表示する。

| 設定名案 | 初期値 | 保存・適用単位 |
| --- | --- | --- |
| choiceCount | 4（正解1＋ダミー3） | ruleset_versions.config |
| answerTimeMs | 10000（解答全体） | ruleset_versions.config |
| revealIntervalMs | 100（調整用仮値） | ruleset_versions.config |
| judgedDisplayMs | 2000（調整用仮値） | ruleset_versions.config |
| fullRevealWaitMs | 10000 | ruleset_versions.config |
| playersPerMatch | 2（指定がないため仮置き） | 大会定義の固定成立条件 |

選択肢数は2以上の整数、時間は正の有限整数、人数は2以上かつ運用上限以内とし、各上限は技術検証で固定する。候補数は正規化後に重複を除いた値で検証し、正解が1個だけ含まれることを保証する。必要なダミーを用意できない問題セットは開始前に拒否する。

変更は新ルール版または新大会定義として発行する。待機列は参加時に版を固定し、人数変更で既存の待機列や開始済み試合を組み替えない。変更後の条件に移る場合は待機取消・再参加とする。選択肢数・解答時間はrulesHash、人数は大会定義に含め、異なる条件を同じ大会の順位へ混ぜない。

### 初期値と問題データ

全文表示後10秒間buzzがなければ無得点で次問へ進み、解答時間切れは誤答として減点・当該問題ロックする。誤答で表示を再開した場合、全文後待ち時間は停止時点の残り時間から再開する案とする。

表示速度は1書記素100ms、判定表示は2秒を調整用の仮値とする。これは性能実績でもユーザー指定値でもない。調整後は新ルール版を発行し、開始済み試合に遡及しない。

初期実装時に独自モック問題を10問以上用意する。本文、正答、カタカナ読み、ダミー候補、解説、出典、許諾とデモ利用可否を記録する。問題データは現時点で未作成。

## ランキング

| 範囲 | 集計キー・条件 |
| --- | --- |
| ローカル | 開催インスタンス、ルール版、期間（開催元の試合を集計） |
| 連合 | 大会ID、共通rulesHash、scoringVersion、期間、認定開催元 |
| 異なるルール | ルール別一覧。素点の一括合算はしない |

順位は勝数降順、次に総得点降順、同値なら同順位という企画提案を初期案とする。表示順だけactorIdで固定する。順位番号は競技順位方式（1,1,3）とする。有効な試合の最高得点が同点なら同点優勝とし、各優勝者の勝数に1を加える。参加数は有効な成立試合への参加数で、同じ結果の再送では増えない。

大会定義に問題セット方針、試合成立条件、期間、認定開催元を固定する。期間はUTCの半開区間 `[startAt,endAt)`、帰属は開催元のfinishedAtを使う。所属元が異なる同名ユーザーは別actor。退会後の記録・表示名の保持は未決。

保存中の結果は順位に加えない。確定済みでもpeerへの同期は別状態で表示する。有効イベントと除外方針が同じ場合に再計算結果が一致する。ローカル除外が異なる場合は差異を表示し、無条件の全peer一致を約束しない。

## 対象外

公開連合、自動発見、モデレーション拡張、ActivityPub連携、世界共通レーティング、クラウド非依存ホスティング。地理的通信遅延差を解消する厳密な公平性も保証しない。
