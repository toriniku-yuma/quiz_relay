# MVP仕様

## 目的と範囲（企画要件）

問題文が徐々に表示され、早押しで解答権を得るマルチ対戦を提供する。名称、素材、画面は独自制作する。各運営者は独立した管理者、DB、Auth、署名鍵を持ち、問題セット・レギュレーション・連合先を選べる。水平スケール用の複数サーバーとは異なる。

プレイヤーは所属元でログインし、他インスタンスのルームへ参加し、戦績を見る。管理者は問題・ルールの版管理、peer承認、結果除外を行う。問題作成者は本文・許容解答・解説・出典・許諾を登録する。管理操作は所有者と権限を検証する。

MVPは2〜4人、7問先取・3回お手つきで失格の1ルールを出発点とする。独立したA（Web技術）とB（別コミュニティ）を構築し、B所属プレイヤーがAの共通大会で対戦し、両方で同じ順位を確認する。単体対戦だけでは完了しない。

## ログインとマッチング（2026-09-08更新）

所属元でメールのマジックリンクとSNSアカウント認証を提供する。MVPのSNS認証はGoogleとする。所属actorの識別はログイン方式によらずhomeOriginとAuth subjectを使い、表示名やSNS名で成績を統合しない。

自動マッチングが完了したら、管理者の開始操作や追加の準備完了操作を待たずに開始する。開始に必要な接続・参加認証・固定問題とルールの準備までをマッチング完了に含める。同じ開催元・大会・ルール版・設定人数の待機列で組み合わせ、設定人数がそろったら開始する。人数は変更可能とし、初期人数は指定がないため2人を仮置きする。MVPの設定範囲は2〜4人を提案する。待機中の取消と同一actorの重複参加防止を用意する。

MVPの自動マッチングでは開始後の新規参加は認めず、切断者の参加記録は保持する。試合中に開催元が接続中のactorを1人以下と判定した時点で、再接続猶予を設けず即座に無効試合とする。0人も対象。同じactorの複数接続は1人と数える。待機中には適用せず、FINISHED後の切断でも無効化しない。無効試合は勝数・総得点・参加数のすべてから除外し、終了理由を表示する。

## フロントエンド構成

React + TypeScript + Tailwind CSSを採用し、Viteでビルドする。画面や繰り返すパーツはReactコンポーネントとして実装する。紹介SPAとは独立したゲームアプリケーションにする。[実装方針](development.md)と[採用判断](adr/0003-tailwind-css.md)を参照。

| 画面 | 必須情報・操作 |
| --- | --- |
| ホーム | 運営方針、開催ルーム、ルール、承認peer、所属ログイン |
| マッチング・ロビー | 開催元、大会、参加人数、固定ルール版、問題セット方針、参加・待機取消。マッチング完了後に自動開始 |
| 対戦 | 表示済み本文、大きな早押し操作、解答権保持者、締切、各参加者の正解数・お手つき数・失格状態・得点、解答者本人のカタカナ選択パネル |
| 結果 | 各問の正誤と得点、保存中／確定、ランキング反映状況 |
| ランキング | ローカル／連合、大会、期間、ルール版、勝数・総得点・参加数、最終同期時刻 |

クイズを画面の主役にする。インスタンス情報と同期状態は参加条件や結果の信頼性に関わる場所に出し、内部ログは管理画面へ置く。接続断・再接続中は操作状態を明示する。タッチとキーボード操作、フォーカス、色以外の正誤表示に対応する。開催地域の表示方法は実測可能性を検証し、RTTを表示する。DOの配置指定を厳密な開催地域保証と表示しない。

### ビジュアルデザイン（2026-09-08回答反映）

フラットデザインを基本とし、簡潔で余計な装飾のない、一見するとチープに見えるほど素朴な見た目にする。デザインで勝負するゲームではなく、あくまでクイズゲームとしての役割に一貫していることを演出するための意図的な方針とする。単色の面、必要最小限の罫線、文字を中心に構成し、装飾目的のグラデーション、光沢、背景模様、過剰な影やアニメーションは加えない。読みやすさ、操作対象の識別、フォーカスや状態表示は維持する。

回答ボタンはフラットな表現を保ちながら、物理的な押しボタンのように凸状に見せる。早押しボタンとカタカナ選択パネルの回答ボタンに、単色の天面と側面・下端の段差を設け、押下時は天面が沈んで段差が小さくなる表現にする。立体感は操作の手掛かりとして限定し、写実的な質感や光沢は付けない。押下不可の状態も判別できるようにする。

具体的な配色、フォント、寸法はまだ指定されていない。この方針に沿って初期実装時に具体化する。採用理由は[ADR 0005](adr/0005-visual-design-and-sound.md)に記録する。

### 効果音（2026-09-08回答反映）

ゲーム内のイベントに効果音を割り当てられるようにする。音源の選定・配置と実際のイベントへの割り当てはユーザーが手作業で行う。初期実装ではイベントと音源の対応を1か所で編集できる設定と、その手順を用意し、音源を自動で選定・割り当てしない。専用の割り当て画面は現時点の要件に含めない。

対象イベントの初期案は早押し操作、文字選択、正解、誤答、試合開始、試合終了とする。具体的なイベント一覧と音源形式・配置先は初期実装時に具体化する。未割り当てのイベントは無音で動作し、音源の読み込み・再生ができない場合もゲーム進行を妨げない。ミュートを用意し、音がなくても表示で状況を把握できるようにする。

## レギュレーション

任意コードは実行せず、サーバー検証可能な宣言的設定とする。AI採点・曖昧一致は対象外。

| 分類 | 設定 |
| --- | --- |
| 出題 | ジャンル、問題セット版、問題数、文字表示速度 |
| 解答 | 制限時間、Unicode正規化方式、前後空白除去、許容解答一覧 |
| 採点 | 正解数、お手つき数、当該問題の再解答ロック、失格。加点・減点は従来提案 |
| 終了 | 勝利に必要な正解数、失格となるお手つき数 |

勝敗は得点ではなく正解数とお手つき数で決める。先に7問正解した参加者が勝利し、試合を終了する。誤選択または1文字の解答時間切れを1回のお手つきと数え、同じ試合で累計3回に達した時点で失格となり、その試合の残りすべての問題で解答権を失う。1・2回目は当該問題だけ再解答不可で、次問から参加できる。正解数・お手つき数は試合開始時に0にする。失格者は優勝対象から除外する。失格していない参加者が1人以下（全員失格も含む）になった時点で即座に無効試合とし、勝数・総得点・参加数には加算しない。当該問題だけの誤答ロックではこの人数を減らさない。問題を使い切った場合はその時点の成績で勝敗を決めて終了する。具体的な比較・同数時の処理は下記の仮案を参照する。従来の10問固定終了と最高得点による同点優勝は、このルールには適用しない。

正解+10点・誤答-5点は得点集計の従来提案として残すが、勝敗条件には使わない。採用とランキングの総得点の扱いは未決。減点は `incorrectPenalty: 5` のような非負の量を設定し採点で引く提案とする。負数禁止を最終得点に誤適用しない。整数、有限値、上下限、文字数、列挙値を検証し、各上限は実装前に確定する。

開始時に `rulesetId / version / rulesHash / questionSetVersion / scoringVersion` と使用問題の `questionId / questionVersion` を固定する。ルール・問題セットの編集は新しい版を発行する。問題改訂は新しいquestionIdを発行し、内部的には別の新規問題として扱う。同じquestionIdの版を増やす方法で改訂しない。既存の問題・セット・進行中の試合・過去結果は書き換えず、新問題を採用するセットは新しいセット版にする。改訂元は新規出題停止にし、以後に開始する試合では旧セット版からも使わない。待機中に対象問題が停止された場合はその固定セットでは開始せず、待機取消・更新済みセットへの再参加とする。開始済み試合の固定内容と過去記録は保持する。改訂元との専用の関連付けはMVPでは設けない。

### カタカナ選択式解答

解答権保持者が、1文字分ずつ表示されるカタカナ選択パネルから文字を選ぶ。各パネルに正解候補と引っ掛け用の候補を用意する。自由入力はMVPに含めない。初期値は正解1個＋ダミー3個の4択。誤選択した時点で誤答とし、お手つきを1回加算し、当該問題ロックと累計3回での失格判定を行う。制限時間は1文字ごとに数秒とする。最初のパネルをサーバーで有効化した時点から計時し、正しい文字を選んで次のパネルを有効化するたびに、その文字の持ち時間を新しく与える。再送・再接続・同じパネルの再表示では期限を延長しない。ユーザーの初期値選定の委任に基づき、1文字3秒を調整用の初期値とする。選択肢数と制限時間は調整可能にする。

問題データには表示用の正答と、パネル用のカタカナ読みを分離して登録する。NFKC→trimの後に書記素単位へ分割し、サーバーで完全一致判定する。NFKCだけではひらがなからカタカナへの変換は行われないため、パネル用読みはカタカナとして登録・検証する。長音・小書き文字を許容し、表記揺れは明示した許容読みとして扱う。MVPのモックは1問につきパネル用読み1通りから始め、複数読みを使う場合の候補分岐は別途契約を確定する。

正答位置、正答全文、将来のパネルはクライアントへ先送りしない。サーバーが当該文字の候補を生成し、解答者本人だけへ送る。候補に含まれる文字と正答そのものの先行公開を区別する。

### 調整可能な設定

数値は実装に散在させず、初期設定を1か所で定義する。実行時の正はDBの版付き設定とし、定数は新しい設定を作成するときの初期値に使う。UIは試合に固定された設定を表示する。

| 設定名案 | 初期値 | 保存・適用単位 |
| --- | --- | --- |
| choiceCount | 4（正解1＋ダミー3） | ruleset_versions.config |
| characterAnswerTimeMs | 3000（1文字3秒、調整用初期値） | ruleset_versions.config |
| correctAnswersToWin | 7 | ruleset_versions.config |
| mistakesToDisqualify | 3 | ruleset_versions.config |
| revealIntervalMs | 100（調整用仮値） | ruleset_versions.config |
| judgedDisplayMs | 2000（調整用仮値） | ruleset_versions.config |
| fullRevealWaitMs | 10000 | ruleset_versions.config |
| playersPerMatch | 2（指定がないため仮置き） | 大会定義の固定成立条件 |

選択肢数は2以上の整数、時間は正の有限整数、人数は2以上かつ運用上限以内とし、各上限は技術検証で固定する。候補数は正規化後に重複を除いた値で検証し、正解が1個だけ含まれることを保証する。必要なダミーを用意できない問題セットは開始前に拒否する。

変更は新ルール版または新大会定義として発行する。待機列は参加時に版を固定し、人数変更で既存の待機列や開始済み試合を組み替えない。変更後の条件に移る場合は待機取消・再参加とする。選択肢数・解答時間はrulesHash、人数は大会定義に含め、異なる条件を同じ大会の順位へ混ぜない。

### 初期値と問題データ

全文表示後10秒間buzzがなければ無得点で次問へ進み、各文字の解答時間切れはお手つき1回として当該問題ロックし、累計3回で失格とする。誤答で表示を再開した場合、全文後待ち時間は停止時点の残り時間から再開する案とする。

表示速度は1書記素100ms、判定表示は2秒を調整用の仮値とする。これは性能実績でもユーザー指定値でもない。調整後は新ルール版を発行し、開始済み試合に遡及しない。

初期実装時に独自モック問題を10問以上用意する。本文、正答、カタカナ読み、ダミー候補、解説、出典、許諾とデモ利用可否を記録する。問題データは現時点で未作成。

## ランキング

| 範囲 | 集計キー・条件 |
| --- | --- |
| ローカル | 開催インスタンス、ルール版、期間（開催元の試合を集計） |
| 連合 | 大会ID、共通rulesHash、scoringVersion、期間、認定開催元 |
| 異なるルール | ルール別一覧。素点の一括合算はしない |

順位は勝数降順、次に総得点降順、同値なら同順位という企画提案を初期案とする。表示順だけactorIdで固定する。順位番号は競技順位方式（1,1,3）とする。有効な試合で7問先取、または問題枯渇時の判定により勝った参加者の勝数に1を加える。得点が同点でも同点優勝にはしない。問題枯渇時は、失格していない参加者の正解数を比較し、単独最多なら勝利、最多が同数なら試合を引き分けとして全員の勝数加算なしとする仮案。引き分けも有効試合として参加数と総得点を集計する仮案であり、比較・同数時の処理は未確定。参加数は有効な成立試合への参加数で、同じ結果の再送では増えない。

大会定義に問題セット方針、試合成立条件、期間、認定開催元を固定する。期間はUTCの半開区間 `[startAt,endAt)`、帰属は開催元のfinishedAtを使う。所属元が異なる同名ユーザーは別actor。退会後の記録・表示名の保持は未決。

保存中の結果は順位に加えない。確定済みでもpeerへの同期は別状態で表示する。有効イベントと除外方針が同じ場合に再計算結果が一致する。ローカル除外が異なる場合は差異を表示し、無条件の全peer一致を約束しない。

## 将来機能（MVP対象外・2026-09-08要望）

- 自動マッチングはElo（イロ）系レーティングに基づく組み合わせへ拡張する。MVPの人数ベースの自動開始は維持し、レーティング計算とマッチングへの利用は後続機能とする。
- レーティングに応じて出題難易度を変える。計算式・適用範囲、人数差への対応、許容レート差、難易度の付け方と選定方法は、基本のクイズ機能が完成してから具体化する。現段階では詳細パラメーターを固定しない。
- レート戦以外にルーム制のマッチを設け、準備完了で開始する。ルーム戦は途中参加を認め、パスワード付きのプライベートマッチも提供する。準備完了の必要人数、途中参加の反映タイミング・初期成績・終了条件、切断時の扱いとパスワード設定は基本的に部屋内の設定で決める。ルーム戦はカジュアル戦として、レーティング更新とローカル・連合ランキングの勝数・総得点・参加数のすべてから除外する。設定項目の型・上限、試合中の設定変更の適用時点、パスワードの安全な保存・照合方法は将来実装時に具体化する。

これらの参加条件・結果契約は将来のルーム戦向けに別途定義し、MVPの開始後参加禁止や成立条件をそのまま適用しない。

## 対象外

公開連合、自動発見、モデレーション拡張、ActivityPub連携、世界共通レーティング、クラウド非依存ホスティング。地理的通信遅延差を解消する厳密な公平性も保証しない。

Google Fontsの[Noto Sans JP](https://fonts.google.com/noto/specimen/Noto+Sans+JP)を採用。癖の少ない日本語サンセリフとして本文・見出し・入力欄・ボタンに使い、Tailwindのfont-sansへ集約する。Google Fonts CSS APIで400〜800の可変ウェイトを読み込み、display=swapで読込中も代替フォントを表示する。文字列を限定するtext指定は使わない。全Unicode文字の収録保証ではなく、未収録文字・配信失敗時は端末の日本語フォント等へフォールバックする。検証結果のコード表示は等幅を維持する。
