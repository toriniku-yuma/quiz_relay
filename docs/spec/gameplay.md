# 対戦・回答・レート

[ドキュメント一覧](../README.md)

**ランクは7問先取。3回お手つきで失格です。**
部屋の勝敗は [部屋マッチ](rooms.md) を見てください。
仕様と実装状況は分けて扱います。[検証記録](../history/verification.md)。

## ログインから開始まで

1. 所属元でメールのマジックリンク、またはGoogleでログインする。
2. 開催元・固定版・ルール版・人数・実力帯が同じ待機列へ参加する。
3. 設定人数の接続・参加認証・固定問題・ルールの準備が揃ったら自動開始する。

管理者の開始操作や準備完了ボタンは不要です。初期人数は4人、現在の設定範囲は2〜4人。
人数はインスタンス管理の「対戦の参加設定」、またはコンフィグで指定し、DBの不変な対戦定義に保存します。
待機取消と同一actorの重複参加防止を用意し、開始後は新規参加を認めません。切断者の参加記録は残します。
自動マッチの待機は対戦中として表示しません。候補登録やページ移動では参加処理・待機と接続を維持します。本人の取消、または最後の接続の切断を検知した時点で待機列から除外します。同じ本人の別タブが接続中なら、切断だけでは解除しません。初回接続前の予約には既存の60秒期限を使います。取消・切断より先にサーバーで開始済みなら試合を保持し、開始後の30秒復帰猶予を適用します。
本人はhomeOriginとAuth subjectで識別します。ログイン方式・表示名・SNS名で成績を統合しません。

## 実力に合わせた出題

**初心者のランク対戦では初級問題だけを出します。** 答えられない難問ばかりにならないよう、参加者の実力に応じて出題できる難易度の上限を設けます。
中級者には初級・中級、上級者には全難易度を出せます。
同じ実力帯の参加者で組み合わせます。人数不足でも実力帯を自動で広げず、同じ帯の人数が揃うまで待機します。
開催インスタンスのレートで実力帯を判定します。管理者が境界を設定でき、初期値は1200未満が初級、1200以上1600未満が中級、1600以上が上級です。
初参加はレート1000から始め、初期設定では初級として参加します。
出題割合は実力帯ごとに管理者が設定します。初期値は初級帯が初級100%、中級帯が初級30%・中級70%、上級帯が初級10%・中級30%・上級60%です。
割合設定でも、その帯の出題上限を超える難易度は指定できません。
カジュアルマッチでは実力帯を分けず、回答者・問題の難易度を混ぜて対戦できます。
問題の抽選は[ランクの自動出題](questions.md#ランクの自動出題)に従います。

## 勝敗

運営が確定後の勝敗・レートを手動で書き換える機能は設けません。保存データに矛盾があれば、自動上書きせず運営へ知らせます。

| 条件 | 結果 |
| --- | --- |
| 誰かが7問正解 | その人が勝利し終了 |
| 誤選択・1文字の時間切れ | お手つき1回。その問題では再回答不可 |
| お手つき累計3回 | 失格。残りの全問題で解答権と優勝資格を失う |
| 未失格者が1人以下（全員失格を含む） | 即INVALID。復帰猶予なし |
| 問題を使い切る | 未失格者の正解数が単独最多なら勝利、最多同数なら引き分け |

正解数・お手つきは試合開始時に0へ戻します。1・2回目のお手つき後は次問から回答できます。
その問題だけの誤答ロックは、未失格者数を減らしません。

ルールと出題候補は開始時に固定。後の追加・改訂・停止で進行中の試合や過去結果を書き換えません。
任意コード・AI採点・曖昧一致は使わず、サーバーで検証できる設定にします。
ジャンル・セット版・問題数・文字速度・解答期限・正規化・許容解答・ロック・失格・勝利条件を設定として扱います。

## ひらがなで回答する

1. 早押しで解答権を得る。
2. 本人だけに届くパネルから1文字ずつ選ぶ。常に4択。正しい次文字を全て含め、残りをひっかけ・ダミーで埋める。
3. 登録した正解読みに到達したら正解。誤選択・期限切れはお手つき。

自由入力はMVP対象外。表示用正答と入力用ひらがな読みは別に保存します。
NFKC → trim → 書記素分割の後、サーバーで完全一致判定します。
NFKCはカタカナをひらがなに変換しないため、読みはひらがなとして登録・検証します。長音・小書きを許可し、表記揺れは許容読みとして明示します。

現在は1問1読み。初期の作問機能では複数読みを受け付けます。
最初に登録正解へ到達した時点で終了します。分岐・候補数・不足時のダミー補充は [作問仕様](questions.md) も参照してください。
正答位置・正答全文・将来パネルを先送りしません。現在の候補文字と、答え自体の公開は区別します。

### 期限

最初のパネルをサーバーで有効化した時点から計時します。
正しい文字で次のパネルへ進むたびに持ち時間を与え、再送・再接続・同じパネルの再表示では延長しません。
期限と同時の入力は時間切れです。
全文表示後10秒間buzzがなければ無得点で次問へ進みます。誤答後の全文待ちは、停止時の残り時間から再開します。

## 初期値と変更

| 設定 | 初期値 | 保存先 |
| --- | --- | --- |
| choiceCount | 4固定・変更不可 | ruleset_versions.config（既存の保存項目） |
| characterAnswerTimeMs | 3000ms（調整用） | 同上 |
| correctAnswersToWin | 7 | 同上 |
| mistakesToDisqualify | 3 | 同上 |
| revealIntervalMs | 100ms／書記素 | 同上 |
| judgedDisplayMs | 2000ms | 同上 |
| fullRevealWaitMs | 10000ms | 同上 |
| playersPerMatch | 4 | 対戦定義の固定成立条件 |

回答パネルは全モードで4択固定です。管理画面・JSON・APIから数を変更できる仕様にはしません。
時間は正の有限整数、人数は2以上かつ運用上限内。現行の許容範囲は[設定手順](../guides/configuration.md)に従います。
現在は正解1文字と登録ダミーで候補数を満たすか開始前に検証します。

初期値を1か所にまとめ、実行時はDBの版付き設定を正とします。UIはその試合に固定した値を表示します。
変更は新ルール版・対戦定義として発行。既存形式のchoiceCountは4固定とし、期限とともにrulesHash、人数は対戦定義に含めます。
待機列は参加時の版を維持し、人数変更でも組み替えません。新条件へ移るには取消・再参加します。
100ms・2秒は初期設定値であり、性能の保証値ではありません。

### 初期問題と旧版

独自問題を10問以上用意する方針に対し、9月11日に12問を作成・デモ利用承認済みです。
本文・正答・読み・ダミー・解説・出典・許諾・デモ利用可否を記録します。
投入データは `supabase/seeds/mock-hiragana.json`、テスト用は `tests/fixtures/questions.ts`。アプリには同梱しません。
現在のCLIは新questionId＋旧問題停止＋新しい順序付きセットで改訂しますが、将来の作問・審査・自動出題をこの方式に限定しません。
DB読込・結果保存は実装済み。[保存設計](../design/schema.md)を参照してください。

## 選んだ文字の共有

`showSelections` は試合共通。初期オンで、旧開発参加画面では最初の参加者の値へ揃えます。開始後は変更しません。
オンなら受理済み文字（誤答も含む）を回答者名とともに順番に表示し、次のbuzzか次問まで残します。
未選択の正解・将来パネルは公開しません。オフはsnapshot・差分のresponseをnullにし、回答履歴を表示しません。

履歴と設定をDOに保存し、再送で二重追加せず、復帰後も同じ履歴を返します。
パネル・ダミー・選択済み文字はひらがな。長音・小書き・濁点は維持し、問題本文は変換しません。
開発ルームは `1b-hiragana:room-N`、タブ保存キーも新版へ分離。旧試合を変換・削除しません。

## 切断と復帰

| 接続中のactor | 対応 |
| --- | --- |
| 2人以上 | 進行・解答期限を継続 |
| 1人以下（0人を含む） | 一時停止。最初の不足検知から30秒以内に2人以上へ戻れば再開 |
| 30秒の期限一致・超過 | INVALIDで確定。後の再接続で復活させない |

同じactorの複数タブは1人と数えます。1→0人、sync、DO復帰では猶予を延長しません。
再開後に再び不足すれば、新しい30秒を開始します。待機中・FINISHED後には適用しません。

停止中は本文・判定表示・解答の残り時間と、パネルID・選択位置・順序を保存します。
新しいbuzz・文字選択は拒否。受理済みコマンドの再送には保存済みACKを返します。
再開後の期限は再開時刻＋残り時間。すでに期限切れの文字に追加時間を与えません。
猶予期限もDOへ保存し、全員切断中もAlarmで終了します。
死活確認は5秒間隔・15秒無応答。切断の検知待ちと30秒の復帰猶予は別です。
通常の再接続・パネル再表示では期限を変えません。

## レート・ランキング

初期レートは1000。開催インスタンスごと・全期間で集計し、下限に丸めません。
カジュアルマッチと部屋はレート・ランキングの全指標に影響しません。現在の正式自動マッチングはランクとして表示します。

| 終了時の条件（上の条件を優先） | 差分 |
| --- | --- |
| 強制離脱、失格、または未復帰 | -20。重複減点なし |
| INVALIDで接続中かつ未失格 | +20（それ以外は-20） |
| 通常勝利／敗北 | +20／-20 |
| 引き分け | 0 |

全員切断なら全員-20。一時切断から復帰できた人への追加減点はありません。
新しい対戦・部屋ロビーへの参加が成立すると、前の試合から本人だけを強制離脱させます。開始済みランクマッチでは本人を失格・切断として固定し、終端結果で-20を一度だけ反映します。開始前の待機取消・切替では結果を作らず減点しません。終了済みの原本は変更しません。カジュアルマッチ・部屋の強制離脱はレート差分0です。
レート降順・同値は同順位（1,1,3）、actorIdは表示順だけに使います。

再送・再集計・終了後の接続変化で二重反映しません。開催元Aの対戦・配送でBの通常レートを変えません。
大会集計・サーバー横断の共通順位は対象外です。

### 保存中と確定

終了時の参加者状態・差分をDOへ固定します。
結果・参加者差分・outbox原本をPostgresへ同時保存し、commit確認とDO保存が終わってから「確定」と表示します。
それまでは「保存中」で、ランキングへ加えません。旧DOだけの結果は遡って集計しません。宛先別の外部配送は未実装です。

## 履歴と公開範囲

- 一般公開は表示名・レート・順位まで。同じ試合の参加者には正解数・お手つき・勝敗を共有する。
- 個別履歴と出題済み問題の振り返りは、その試合に参加した本人だけ。ランキングから他人の履歴を公開しない。他人のactor・試合ID指定も拒否する。
- 本人履歴は最新20試合から表示し、20件ずつ追加取得できます。ランキングは上位100人。履歴には勝敗・終了日時・正解数・お手つき・本人のレート差分を表示する。
- ランキング表の上とランクマッチ画面のページ見出し直後に、自分の順位・レートを表示する。上位100人の一覧外でも本人の順位を取得する。未参加・除外中など順位が付かない場合は「—」とし、レートは保持して表示する。初期レートは1000。本人表示にも同順位・開催インスタンス・保存済みランク結果の集計条件を適用し、保存確定後に更新する。カジュアルマッチ・部屋・ゲストには表示しない。
- 対戦履歴 `/history/` とランキング `/ranking/` は別ページにし、サイドバーから直接開く。履歴は「すべて／ランク／カジュアルマッチ／部屋」で絞り込むテーブルとし、終了日時・種別・勝敗・正解数・お手つき・レート差分・詳細へのリンクを表示する。
- 試合の詳細では参加者の成績・出題済み問題の振り返り・通報を表示する。マッチ画面には現在の試合結果と「試合の詳細」「対戦履歴」のリンクを置き、過去の一覧やランキングは専用ページだけに表示する。
- 運営の不正調査は別権限。担当インスタンスのモデレーターと組織管理者が管理範囲を閲覧する。

未出題問題・審査者名・運営用改訂履歴・非公開の根拠は、振り返りにも配信しません。
本人履歴APIは実装済みですが、マイページ・振り返り全体の完成を意味しません。

共有を許可した別開催元の結果は、所属元の本人履歴に開催元付きで表示します。
振り返りは開催元の結果画面へ移動し、そこでも本人認可します。

### 表示名の変更

表示名は組織内で一意とし、変更回数の制限は設けません。プロフィール・ランキングは即時更新し、待機中・対戦中・過去結果は参加時の名前を保持します。
文字数・重複判定・退会時の例外は[組織の表示名仕様](organization.md#表示名とプロフィール)に従います。
