# 作問・審査・出題

[ドキュメント一覧](../README.md)

**まず投稿方式を確認してください。問題の承認・使用停止・作問者資格は別の状態です。**

## 画面と移動

サイドバーは通常利用の「対戦」「作問」と、管理用の「審査」「問題管理」「インスタンス管理」「組織管理」を分けます。作問一覧には担当権限にかかわらず本人の問題だけを表示します。
「問題管理」は開閉メニューではなく専用のメニューページへ移動します。ページ内は「問題」（全問題）、「分類・整理」（カテゴリ管理・タグ統合）、「作問者」（作問者資格管理）の見出しと縦並びのリンクで構成します。担当権限のないリンクと空の区分は表示しません。各管理ページには問題管理へ戻るリンクを置きます。
「審査」の審査待ちは専用ページに分け、提出済みの問題だけを表示します。通報・再審議とカテゴリ変更申請もサイドバーから個別に開きます。
自分の問題・全問題・審査待ちの一覧は初期10件、10・30・100件から表示件数を選べます。総件数・表示範囲・現在ページを表示し、前へ／次へで移動します。検索・状態・カテゴリ・件数・並べ替えを変更すると先頭ページへ戻ります。検索と絞り込みは閲覧権限内の全件に適用し、サーバーが該当ページだけを返します。
問題文・正答・状態・カテゴリ・作問者・更新日時の列見出しで並べ替えます。初期順は更新日時の降順で、[共通テーブルの操作](organization.md)に従います。一覧条件・並べ替え列・方向とページ番号はURLに保持します。詳細からの「一覧に戻る」とブラウザーの戻る操作で復元し、審査待ちから開いた詳細は審査待ちへ戻ります。条件変更だけでは入力欄のフォーカスやスクロール位置を移しません。検索・状態・カテゴリ・件数の条件変更中や取得失敗時は古い条件の結果・件数・ページ数を表示しません。同じ対象のソート・ページ送りでは表示中の表を残し、取得成功時に行・件数・ソート方向を一緒に差し替えます。
一覧から新規作成、各問題の編集・提出、JSON取込、作問者資格申請、カテゴリ変更申請へ移動します。各フォームには個別URLを設け、同じページに別用途のフォームを並べません。
問題審査では一覧から個別の審査・停止画面へ移動します。通報・カテゴリ変更申請・資格管理も一覧から対象を選びます。カテゴリ変更・難易度変更・分類用JSONは全問題一覧のポップアップに集約し、旧個別ページは廃止します。カテゴリ管理、タグ統合、投稿設定、出題設定は専用ページです。権限のない管理リンクは表示せず、直接アクセスとAPIでも権限を確認します。
通知の表示・既読は[組織と運営](organization.md)に従います。
作問・審査・履歴・組織管理に再読み込みボタンは常設しません。情報の取得に失敗した場合だけ「再試行」を表示します。入力・保存エラーと取得エラーは区別し、保存成功後の情報取得は自動で行います。
認証・インスタンス確認後は、本文全体を情報取得待ちで置き換えません。検索・状態・件数選択と新規作問の入力欄は先に表示し、問題一覧・カテゴリ候補・保存済みの問題／設定だけを読み込み表示にします。初回取得中に0件や仮の設定値を表示せず、新規入力は候補取得後も保持します。必要な情報を取得するまで保存はできません。履歴・ランキングも見出しを先に表示して、各データ部分に取得状態を示します。
作問・審査の情報取得は画面別に必要なデータだけを返します。新規作問・設定・資格・カテゴリ・タグ管理では問題全件を取得せず、編集・審査・カテゴリ変更申請の詳細は対象の1問に限定します。対戦結果からの統計計算は問題管理一覧で行い、各画面の担当権限はサーバーでも確認します。

### 作問ルールの掲示

新規作成・編集・JSON取込の各ページに、対象インスタンスの作問ルールを掲示するスペースを設けます。フォームの上部でルール本文を確認でき、対象インスタンス名も表示します。問題文・正答・解説・出典の書き方や投稿時の注意など、運営が定める内容を掲示できます。

作問ルールは[インフォメーション](overview.md#インフォメーション)のルールの一項目としてインスタンスごとに管理し、両画面で同じ保存内容を表示します。組織管理者がインスタンス管理から編集し、インフォメーションからも作問ルールを確認できます。
PC・スマートフォンで読めるようにし、ルールの読込・再試行で入力中の問題や取込内容を失わないようにします。

掲示・編集機能は未実装です。[実装計画](../development/plan.md)のインフォメーションと同じ段階で、最終UI調整・総合確認の前に実装・検証します。

### 一覧の統計・選択・一括操作

管理一覧に現在の難易度、自動／固定、正答率、出題回数、未対応通報数、再審議対象を表示します。正答率はランク戦で誰かが正解した回数／出題回数。未出題は「—」です。実力帯・人数を変更すると対象の統計で並べ替え直します。表の内側で横スクロールし、列を過度に圧縮しません。

24pxの共通チェックボックスを使い、見出しのチェックで現在ページを全選択／解除します。一部選択を表示し、ページ・並べ替えをまたいで選択を保持、検索・絞り込み変更時は解除します。選択数を常時表示します。

行のスパナと「一括操作」は共通のポップアップを開きます。カテゴリ、難易度・固定、使用停止／解除、理由付き差戻し、削除／復元に対応します。承認・却下は1問だけで、一括承認・手動再審議は設けません。難易度は管理者のみ、その他は問題管理担当も操作できます。1回の一括変更は500件までです。

削除は通常一覧と出題候補から外す論理削除です。削除済みの絞り込みから復元し、削除直前の投稿状態・使用停止・差戻し停止を維持します。過去の試合と公開版は消しません。

一括変更は権限不足・競合などが1件でもあれば全件変更せず、対象と理由を表示します。同じ要求の再送を記録し、通信結果が不明な間は入力を固定して同じ内容を再試行します。

## 投稿方式と権限

| 投稿方式 | 投稿できる人 | 審査 |
| --- | --- | --- |
| 管理者限定 | 管理者 | 承認済みのみ。自己承認可 |
| 承認作問者限定 | 資格を持つ作問者 | 資格付与とは別に問題を審査 |
| 一般投稿・審査あり（初期値） | ログイン済みユーザー | 管理者・担当モデレーターが承認 |
| 一般投稿・審査なし（非推奨） | ログイン済みユーザー | 事前承認不要 |

設置者が初期管理者兼モデレーターです。自己承認できるのは管理者だけ。
モデレーターの問題は別のモデレーターか管理者が承認します。自己承認の例外設定は設けません。
インスタンス全体を審査なし方式にすることとは区別します。

| 担当権限 | できること |
| --- | --- |
| 作問管理・問題承認 | 担当問題の管理・承認・停止／解除・カテゴリ整理・再審議。資格付与やユーザー処分は不可 |
| 作問者資格管理 | 承認作問者の資格を付与・取消。本人申請の承認と、申請なしの直接付与 |
| ユーザーモデレーション | [処分・調査](organization.md)。作問・資格管理から独立 |
| 管理者のみ | モデレーター任命・権限変更、投稿方式・難易度・作問者名表示・外部連携などの全体設定 |

モデレーターが自分や他人の権限を変更することはできません。
「管理者・モデレーター」とある操作も担当権限が必要です。画面の非表示だけでなくサーバーで認可します。

### 審査なし方式への切替

「審査なし」は、運営による内容の事前確認を行わない非推奨の投稿方式です。
切替時点で審査中の新規投稿・改訂も自動で審査を通します。本人による取下げ・再提出や、運営者の個別承認は不要です。
新規投稿は通常の出題候補へ、改訂は新しく始まる試合へ反映します。進行中の試合・過去結果は変更しません。
形式・必須項目の入力検証と、問題の使用停止は審査とは別に維持します。未提出の下書きや終了済みの却下を、自動公開する操作ではありません。

### その他の投稿方式変更

審査なしから審査ありへ切り替えても、公開済みの問題は維持します。切替後の新規投稿・改訂から審査を適用します。
投稿方式の変更で提出資格を失う場合は、対象者の審査中の申請を終了し、本人の編集用下書きを残します。公開済みの問題は維持します。

## 作問者資格の申請と取消

**作問者資格は、対象インスタンスの「承認作問者限定」方式で問題を投稿するための権限です。**
他のインスタンスには引き継ぎません。管理・モデレーション権限や、問題審査の免除も含みません。

### 申請と付与

| 操作 | 結果 |
| --- | --- |
| 本人が申請 | 申請理由は任意。同じインスタンスで申請中にできるのは1件 |
| 資格管理担当が承認 | 投稿できるようになる。提出した問題は別途審査する |
| 資格管理担当が不承認 | 本人に理由と再申請できる日時を知らせる。待機期間後に再申請できる |
| 資格管理担当が直接付与 | 本人申請なしでも付与できる。申請中なら、その申請も承認済みにする |

不承認後の再申請には、**インスタンスの管理者が設定する待機期間**を設けます。例えば約1か月待たせる運用にできます。
不承認時から待機期間を数え、期間中の再申請はサーバーでも受け付けません。
資格管理権限を持つ担当者だけが、申請の承認・不承認と資格の直接付与・取消を操作できます。

### 取消と再付与

| 対象 | 資格取消後の扱い |
| --- | --- |
| 新規投稿・改訂の提出 | 承認作問者限定方式では提出できない |
| 本人の審査中・差戻し中の新規投稿・改訂 | 審査を終了し、編集用の下書きは残す。承認・通常の却下とは区別する |
| 公開済み・使用停止中の問題 | 状態を維持する。公開改訂の審査を終了しても、公開中の旧版は残す |
| 後日資格を再付与した場合 | 再び提出できる。終了した審査は自動再開せず、本人が提出し直す |

取消理由は記録し、本人にも知らせます。他の作問者の審査は続けます。

**資格取消と投稿制限は別の操作です。** 一般投稿方式では資格が不要なため、資格取消だけでは投稿を禁止しません。
本人の投稿を止めたい場合は個人の投稿制限を、公開済み問題を出題から外したい場合は問題の使用停止を使います。

## 問題に登録する情報

| 区分 | 項目 |
| --- | --- |
| 必須 | 問題文・表示用正答・入力用ひらがな読み・主カテゴリ1つ・解説・自己申告の難易度 |
| 任意 | 公開用出典・複数の補足タグ |
| 提出時に必須・非公開 | 正答の根拠。説明・出典などを記入。外部URL自体は必須ではない |
| 自動記録・運営用 | 投稿者・審査者・本文と正答の改訂履歴 |

根拠は公開用解説・出典と別項目で、投稿者本人・管理者・担当モデレーターだけが閲覧できます。
一般ユーザーへ問題全体の一覧・検索を公開しません。「公開済み」は**出題可能**という意味です。
各問終了後に表示用正答・読み・解説を表示し、試合後も参加した本人だけが出題済み問題を振り返れます。
他人の履歴、未出題問題、審査者名・運営用改訂履歴・根拠から予習できる経路は設けません。

### 1問ごとの入力上限

短い早押し問題として読めるよう、フォーム・JSONとも同じ上限を適用します。文字数は見た目の文字単位で数えます。

| 項目 | 上限 |
| --- | --- |
| 問題文 | 150文字 |
| 表示用正答 | 20文字 |
| 正解の読み | 1種類につき20文字。回答操作は1回の回答につき最大20文字分 |
| ひっかけ | 表示する答え・読みとも各20文字 |
| 公開用解説 | 300文字 |
| 非公開の正答根拠 | 1000文字。審査用であり、対戦画面には表示しない |
| 出典 | URLを含め1000文字 |
| タグ | 1問10個まで、1個32文字 |

上限超過は入力時・提出時に表示して修正を求め、勝手に切り詰めません。過去の回答履歴や保存済みの原文は上限変更を理由に切り詰めません。

### 作問者名の表示

作問者名は初期状態では非表示です。管理者が表示を有効にすると、問題終了後・振り返りに表示します。投稿者本人の選択にはしません。
非表示でも投稿者の自動記録は保持します。審査者名・改訂履歴を一般公開する設定は設けません。

投稿者本人は、自分の申請内容・改訂履歴・審査理由を確認できます。審査者名は本人にも公開せず、担当運営者だけが確認できます。
作問者名・表示設定の変更は次に始まる試合から反映します。過去の振り返りは、その試合開始時の名前・表示設定を維持します。ただし、退会時は過去分も匿名化します。

## 審査と改訂

| 操作 | 結果 |
| --- | --- |
| 承認 | 使用停止中でなければ出題候補へ |
| 理由付き差戻し | 修正・承認まで出題停止。同じ申請を修正して再提出できる。手動の使用停止は独立して維持 |
| 理由付き却下 | 申請を終了。作り直すなら新規申請 |
| 審査中に修正したい | 取下げ → 本文・正答・根拠を編集 → 再提出 → 審査 |
| 公開後の改訂・審査あり | 改訂案を再審査。その間は旧版を使う |
| 公開後の改訂・審査なし | 改訂確定後、新しく始まる試合に反映 |
| 使用停止 | 担当運営者が操作。開始済み試合には遡らない |
| 再審議対象化 | 自動停止しない |

審査中の内容は直接差し替えず、取下げて編集・再提出します。運営の承認操作と同時になった場合も、取り下げた古い内容を承認できないようにします。
画面には現在の状態・取下げ・編集・再提出・審査理由の確認を用意します。
審査への提出と審査なしの改訂確定を区別し、改訂しても停止解除にならないと表示します。
進行中の内容・過去版・改訂履歴は保持します。新questionId方式でも改訂元との関連を失わない設計にします。

## 複数読みとひっかけ

複数の正しい読みを初期の作問機能から登録でき、作問者が許容読みを明示し、審査で確認します。
現在の単一読み実装をサービスの制限にしません。
正解の読みは1問に1〜8種類、各1〜20文字まで登録できます。文字数は見た目の1文字（書記素）で数えます。

最初に登録正解読みへ到達した時点で正解です。
「あめりか」と「あめりかがっしゅうこく」を登録したら「あめりか」で終了。長い読みの入力中でも同じです。
未登録の共通接頭辞では正解にせず、分岐した別の登録読みも受け付けます。「短い読みで確定」ボタンは不要です。

ひっかけは任意で最大16件、「表示する答え＋読み」を登録できます。正解と同じ読みは登録できません。
最初の文字から正答と違っていても登録できます。共通接頭辞を必須にしません。
候補が不足したらシステムがダミー文字を補充します。
読みにはひらがな・小書き文字・濁点・長音「ー」を使えます。同じ読みの重複登録は1件にまとめます。

### 提出時の4択チェック

**正しい次文字が4種類を超える問題は、バリデーションで弾き、申請できないようにします。**
全ての登録正解読みを照合し、回答が続く各入力位置で必要になる異なる次文字の数を確認します。
例えば正しい次文字が5種類必要なら、該当する読み・入力位置と4択に収まらない理由を表示し、修正を促します。正解の一部を自動で削除しません。
画面とサーバーの両方で検証し、新規提出・再提出・改訂提出に適用します。審査なし方式の登録・改訂確定とJSON経由の提出でも省略しません。
回答パネルは全モード・全インスタンスで4択固定です。パネル数を変更する設定は設けません。共有問題も同じ4択の条件を満たす必要があります。

## カテゴリ・タグ・検索

カテゴリの作成・廃止は管理者が行い、投稿者が主カテゴリを1つ選びます。問題の整理・タグ統合は作問管理担当も行えます。
カテゴリ変更は投稿者の申請を運営が確定するか、運営が申請・通報なしで直接変更できます。
本文・正答の改訂審査とは別で、カテゴリだけの変更なら難易度集計を引き継ぎます。
カテゴリを廃止するときは移動先を指定し、対象問題を一括で移します。分割するときは運営が対象を選び、移動先へ振り分けます。
どちらも過去の試合記録・問題版を変更せず、難易度集計を維持します。

### JSONでカテゴリを一括分類する

**AIなどで作成した分類結果をJSONで読み込み、既存問題のカテゴリへ一括反映できます。**

1. 運営が管理対象の問題を選び、分類用JSONを出力する。問題ID・本文・表示正答・現在のカテゴリと、移動先に使えるカテゴリID・名称を含める。
2. AIや手作業で「問題IDと移動先カテゴリID」の対応を作る。新しいカテゴリが必要なら、先に管理者が作成する。
3. 分類結果のJSONを読み込む。問題ごとの変更前・変更後を表示し、運営が確認して一括反映する。

読み込みは既存問題のカテゴリ変更として扱い、問題を新規投稿したり本文・正答・審査状態を変更したりしません。
JSONに含まれない問題は変更しません。不明なID・同じ問題への重複指定・権限外の問題があれば、該当箇所を表示して反映前に修正できるようにします。
出力・反映とも担当範囲の権限を確認します。分類用出力に非公開の根拠・審査記録・個人情報は含めません。

### タグと検索

タグは作問者の自作問題の整理・検索と、管理者・作問管理モデレーターの管理対象の検索に使います。
一般には表示せず、出題条件にも使いません。候補から未出題本文・正答・一覧を漏らしません。

- 同じインスタンスの既存タグを候補表示し、適切な候補がなければ新規作成できる。
- 管理者・作問管理モデレーターは同義タグを統合できる。旧名は別名として残し、旧名の入力・検索でも統合先が見つかる。
- 「日本史」と「江戸時代」のような範囲の違うタグは別。意味が似ているだけで自動統合しない。
- 全角・半角、英字の大小、前後の空白・連続する空白を揃えて同じタグとして照合する。表示名と別名は保持する。初期は階層・複雑な関連付けを設けない。

タグだけの変更でも難易度集計を維持します。

運営の問題検索では本文・表示正答・読みを検索し、カテゴリ・タグ・審査／使用状態で絞り込みます。
審査中・公開中・停止中が対象。検索で候補を絞り、各問題の個別ページを確認して人が重複を判断します。一覧に比較用チェック欄や2問の並列表示は設けません。
同じ答えでも問う知識が違うため、自動却下・統合・類似候補提示は採用しません。この検索を作問管理画面に含めます。

## 通報・再審議・難易度

試合後に出題済み問題を理由付きで通報できます。問題不備とカテゴリ違いは別集計・別しきい値。
カテゴリ違いには正しいと思うカテゴリ名を入力できます。同じ問題版・通報種別・審議回につき1人1件です。
提出後の通報を本人が編集・取り消す機能は設けません。

再審議の初期しきい値は、問題不備・カテゴリ違いともに5件です。しきい値へ到達したら再審議対象にしますが、自動停止はしません。
運営が対応内容と理由を記録して解決し、作問者へ通知します。通報者への通知は行いません。
解決後は過去の通報記録を残し、新たな通報は次の審議回として0件から数えます。
過去の試合結果・レートは変更しません。

難易度はランクの出題範囲と、部屋での問題選択に使います。区分はサーバー設定で定義します。
**作問者の自己申告から始め、十分なデータが集まった問題は実力を考慮した自動推定へ移行します。**
投稿時の難易度申告は必須です。審査あり方式では運営が確認・必要に応じて修正して承認し、審査なし方式では申告値をそのまま使います。
難易度未設定の既存問題は、設定が済むまでランクの出題候補から外します。管理者がまとめて難易度を設定できます。
単純な全体正答率だけで難易度を変えません。試合開始時の参加者レート・対戦人数・問題版と、試合単位の正解成立の有無を使います。
回答機会がなかった人を誤答として扱いません。

| 段階 | 扱い |
| --- | --- |
| 投稿直後・データ不足 | 自己申告を初期値にし、現在の難易度を維持する |
| 十分なデータが集まった後 | 参加者の実力を考慮した推定で難易度を自動更新する |
| 管理者が固定した問題 | 自動更新せず、指定した難易度を維持する。固定解除で自動判定へ戻せる |

上級者の正答率が高いだけで初級へ変更しません。低い実力帯でも易しいと判断する根拠が足りない場合は、現在の難易度を維持します。
推定のために初心者へ出題範囲外の難問を試験出題しません。
### 自動更新の条件

| 条件 | 扱い |
| --- | --- |
| データ量 | 同じ問題の集計世代・実力帯・人数・回答ルール・実力帯設定版ごとに最低50回の出題・異なる参加者20人以上を必要とする。両方を満たしても推定の確かさが不足する間は変更しない |
| 更新頻度 | 1日1回まとめて判定し、新しい難易度は次に始まる試合から適用する |
| 変更幅 | 1回につき1段階まで。境界付近で上下を繰り返さないよう、変更に必要な余裕を設ける |
| 問題改訂 | 本文・表示正答・読み・ひっかけの変更は、新しい版でデータを集め直す。解説・出典・カテゴリ・タグだけなら引き継ぐ |

50回・20人は初期の最低条件であり、推定精度の保証ではありません。
判定にはWilsonの95%区間を使います。現在区分に対応する実力帯で区間の上限が50%未満なら1段階難しくし、1つ下の実力帯で区間の下限が80%を超えれば1段階易しくします。
下位帯の出題実績がない場合は自動で易しくせず、管理者が判断します。データ不足・境界付近・上下の判定が同時に成立する場合は維持します。
新しい出題結果がない日に、同じデータだけで再分類しません。計算式・日次処理・推定上の限界は[難易度設計](../design/difficulty.md)にまとめています。

管理者は問題管理一覧の列見出しで正答率・出題回数・現在の難易度・更新日時などを並べ替え、選択した問題の難易度を一括変更できます。正答率・出題回数は選択中の実力帯と対戦人数の集計を使い、初期値は両方とも全体です。
例えば「初級」の問題を正答率が低い順に並べ、見直す問題を選んで「中級」へ変更します。
正答率と出題回数を併記し、対戦人数別の集計を選んで比較します。未出題は正答率0%と区別します。
難易度だけの変更では正答率の元集計や過去の試合記録を変更しません。


**正解成立率 = 誰かが正解した出題回数 ÷ 有効な出題回数**

誰も押さず終了した問題も分母に含めます。回答機会のない個人を誤答にしません。
ランクだけを実力帯・対戦人数別に集計し、正答率と出題回数を表示します。カジュアルマッチ・部屋はこの集計に含めません。
出題回数を併記して、少数の出題による正答率と十分に出題された結果を区別できるようにします。
集計を引き継ぐ改訂の範囲は上の「自動更新の条件」に従います。INVALID前に終了した問題は集計し、進行途中は除外します。

## ランクの自動出題

1. 承認が必要なら承認済み、不要なら登録済みで、停止されておらず、参加者の実力に応じた出題範囲に入る問題を候補にする。
2. 実力帯の設定割合で難易度を抽選する。候補のない難易度は外し、許可範囲内の残りの割合を比例調整する。
3. 選んだ難易度の候補があるカテゴリから設定割合で抽選する。初期はカテゴリごとに均等。問題数には比例させない。
4. そのカテゴリからランダム選出する。同じ試合では重複させず、別試合では再出題できる。

手動セットは必須にしません。割合は抽選確率であり、試合ごとの厳密比率ではありません。
候補のないカテゴリは除外して残りの割合を比例調整します。割合0のカテゴリは有効化しません。
一部の難易度に候補がない場合は、その実力帯で出題を許可された難易度の中で割合を調整します。
例えば中級問題がない場合、中級帯でも初級問題だけで開始できます。許可範囲外の難易度で補いません。
初心者には初級問題だけ、中級者には初級・中級、上級者には全難易度を出せます。問題不足を理由に初心者へ難しい問題を出しません。
同じ実力帯で組み合わせ、人数不足でも別の帯を混ぜません。実力の判定と出題割合は[対戦仕様](gameplay.md#実力に合わせた出題)に従います。難易度未設定の問題はランクの候補に含めません。
プレイヤー自身によるカテゴリ・難易度選択は部屋向けです。
候補は開始時に固定し、後の追加・改訂・停止は次の試合から反映します。
枯渇時は未失格者の正解数で単独最多なら勝利、同数なら引き分け。即時無効・勝利条件を優先します。

| 状態 | 対応 |
| --- | --- |
| 実力帯の候補0件 | 該当帯の新規受付・開始を停止。理由を示して待機解除。他の帯・カジュアルマッチは候補があれば継続し、開始済み試合も継続 |
| 候補が復旧 | 該当帯の候補0による受付停止だけ自動解除。解除された人は自分で再参加 |
| 手動休止・公開状態・モード無効・個人制限 | 候補が戻っても解除しない |

運営には登録・承認・停止・出題設定・共有取得の確認先を案内します。
一般向けの案内に未出題問題や審査専用情報を含めません。持込問題の部屋まで一律に止めません。
大会は対象外です。

## JSON入出力と共有

複数問題をJSONでまとめてインポートし、投稿者本人が自作の投稿問題をJSONで出力・他サーバー等で再利用できます。
読み込みは1ファイル最大500問・2MBまでとし、フォームと同じ入力検証を行います。不正な項目がある場合は場所と理由を表示し、修正するまで取り込みません。
自作問題の出力も1ファイル最大500問とし、2MBを超える場合は500問未満でも分割します。複数ファイルにまたがっても対象問題を欠落・重複させません。
本人は下書き・公開・停止・却下を含む自作問題を出力でき、自分の非公開根拠も含められます。他人の問題・審査者名・運営記録は含めません。
読み込んだJSONは新しい下書きとして登録し、公開・承認状態は引き継ぎません。提出時に通常の投稿資格・検証・審査を適用し、JSONの承認済み状態や権限を信用して省略しません。
他人の問題を本人用出力から取得できず、一般向け一覧にも公開しません。
投稿後の利用・共有は運営が管理し、作問フォームに問題別の共有可否・オプトインを設けません。
権限の一律付与や審査省略を意味しません。

### 管理者・問題管理担当の移行用エクスポート

一覧の出力ポップアップで「選択した問題」と「インスタンス全体」を選びます。選択出力は下書き・差戻し・削除済みを含めてすべて出力します。全体出力は検索やページに関係なく承認済みだけを対象にし、使用停止を含み削除済みは除外します。

version:2の移行JSONに問題内容・根拠・出典・難易度・カテゴリ名・タグ・停止状態・元作問者名・出力元インスタンス名を保存します。ユーザー内部ID・戦績・審査記録は含めません。500問・2MBごとに分割します。

取込は新規の下書きとして作成し、提出時に取込先の資格・審査を適用します。元作問者名・出力元・停止状態を保持します。カテゴリは同名候補を初期選択し、既存カテゴリへ対応付け、管理者は同じ画面で新規作成もできます。カテゴリ作成を含め全件を同じトランザクションで保存します。旧version:1の本人用JSONも引き続き読み込めます。

## 通知と画面の完成条件

審査結果・差戻し・資格承認／取消等は、初期はサイト内通知だけ。メールリンクによるログインは維持します。

通知先の画面にも本人・運営の閲覧権限を適用し、非公開の根拠を漏らしません。

投稿・申請、審査・停止・カテゴリ変更、通報・再審議、設定、出題済み問題の振り返りを画面から行えることを確認します。
画面とサーバーの担当権限を一致させます。CLIだけで完了にしません。
[機能別の計画](../development/plan.md)に従い、機能と画面を同時に整えます。
