# カジュアル・部屋・ゲスト

[ドキュメント一覧](../README.md)

**部屋は非レート戦。参加 → 準備完了 → 部屋主が開始 → 結果 → 同じロビーへ戻ります。**
単体版の完成までに、部屋作成・参加・対戦・結果・再参加の画面を用意します。機能は未実装です。
部屋・カジュアルはレート、ローカル／連合ランキングの全指標、ランクの難易度集計へ反映しません。保存・再試行でも混入させません。

## カジュアルの自動マッチ

カジュアルの初期ルールは4人・7問先取・3回お手つきで失格です。人数は2〜4人で設定できます。
カジュアルは初期状態から自動マッチ方式です。設定人数などの開始条件が揃えば自動開始し、手動開始方式への切替は設けません。
実力帯で回答者を分けず、初心者から上級者まで一緒に対戦できます。
問題も参加者の実力で難易度を制限せず、初級から上級まで出題候補にします。審査・使用停止・共有許可などの利用条件は適用します。
部屋主がカテゴリ・難易度を選ぶ部屋の設定とは別です。

## 部屋へ入る・試合を始める

| 種類 | 参加方法 |
| --- | --- |
| 公開部屋 | 一覧から参加。友人だけに用途を限定しない |
| 非公開部屋 | 一般一覧に載せず招待URLで参加。部屋主は任意でパスワードを設定 |

部屋は作成時に公開を初期選択し、部屋主が非公開へ変更できます。公開・非公開のどちらでも任意でパスワードを設定でき、設定した場合は正しい入力が必要です。
パスワードは初期設定ではありません。変更後のパスワードは新規入室者に適用し、参加済みの人の再接続を妨げません。
招待URLは部屋を閉じるまで有効です。再発行すると古いURLは使えなくなります。
回答者は2〜8人で、部屋主が人数上限を設定します。出題専任者は回答者とは別に1人まで参加できます。
一覧には名称・人数／上限・待機／対戦中・パスワードの有無を表示します。
公開するのは存在と入口まで。未出題本文・正答・運営記録は公開しません。
「誰でも参加」はゲスト・個人制限・外部受入等の条件を免除しません。

開始には **回答者2人以上・全回答者の準備完了・部屋主の開始操作** が必要です。
定員まで集まらなくても開始できます。全員準備だけでは自動開始しません。
出題専任者は回答者に数えず、回答兼任の部屋主は人数・準備確認に含めます。
ロビーに人数と準備状態を表示します。専任1人＋回答者1人では開始不可です。

### 途中入室と次の試合

試合中も入室枠に空きがあれば参加できます。新規入室者はロビー待機。次の問題から回答者に加わることはありません。
待機理由を表示し、進行中の人数・成績・勝敗・終了判定を変えません。正答や未出題内容も配信しません。途中入室者向けの観戦は設けません。
元の参加者の切断復帰は新規入室と区別し、ゲーム共通の復帰期限と本人認証を使います。

終了後は同じ部屋のロビーへ戻る導線を用意し、待機者も次試合へ参加できます。
人数・ルールの変更や部屋主の交代があった場合は全員の準備を解除し、変更後の条件で準備し直します。
全員が再度準備完了し、同じ開始条件を満たして部屋主が開始します。前の準備・成績・失格を引き継ぎません。
待機者を前の試合の参加者・結果へ追加せず、前の保存・本人履歴・振り返りは残します。

## 勝利条件・お手つき

部屋の初期ルールは7問先取・3回お手つきで失格です。部屋主が人数・出題カテゴリ・勝利条件を変更でき、参加者にも表示します。
カテゴリ・難易度をプレイヤーが選ぶ方針です。
ランクの2〜4人・7問先取を、そのまま部屋の上限にしません。

| 勝利方式 | 終了条件 |
| --- | --- |
| 指定正解数の先取 | 最初に指定数へ到達した人が勝利 |
| 指定問題数で競う | 指定数の終了時に、未失格者の正解数最多が勝利。最多同数は引き分け |

方式と対応する数値を設定し、参加前・ロビー・対戦中に表示します。
先取数・出題数・失格回数は1〜100で設定できます。問題数方式では誰も正解しなかった問題も1問と数え、先取による早期終了は加えません。

どちらの方式でも「失格なし」か「指定回数のお手つきで失格」を選び、ルール表示にも出します。
誤答・文字入力の時間切れでお手つき1回となり、その問題には再回答できません。「失格なし」でも同じです。
ランクの初期3回失格は変更しません。

**失格で未失格者が最後の1人になったら、その人の勝利です。**
ランクの「1人以下でINVALID」は適用しません。出題専任者は勝敗に含めません。
問題不足では、未失格者のその時点の正答数で勝敗を決め、最多同数は引き分け。結果に勝敗と終了理由を表示します。

失格者は最多正解者の比較に含めません。
回答者の接続が1人以下になったら試合を30秒停止し、復帰しなければ無効試合（INVALID）にします。

## 持込問題と部屋主

ログイン済みの部屋主が問題を持ち込めます。公開部屋でも利用でき、**簡易作問フォームとJSON読込の両方**を用意します。
JSONを手書きできない人もフォームで作成でき、入力・確認・出題反映まで行えるようにします。
現行CLIの単一読み・source必須・demoAllowedを、そのまま持込形式の制約にしません。

両経路とも審査なしでその部屋に使います。4択の成立などの入力検証は行います。
持込問題を使う試合では通常の問題を混ぜず、持込セットをランダムな順番で出題します。同じ試合で同じ問題を繰り返さず、次の試合では順番を改めて抽選します。
他の部屋・共通問題・ランク候補へ自動登録しません。共通問題として使うには、資格・必須項目・審査条件を満たす通常投稿を行います。
入力画面には「部屋用であり共通問題への投稿ではない」と示します。

作成者本人だけが問題セットを保存・編集・出力・削除して再利用できます。他の参加者にはその権利を付与しません。
保存したセットは、作成者が削除するまでアカウント保有中は保持します。
部屋主交代でも、元の作成者の問題を保存・編集・出力する権利は得ません。
「部屋限定」は部屋終了時の全記録削除を意味せず、振り返りと再利用の保存は区別します。JSON出力・作問画面の複数インポートは採用済みです。
参加者は出題済みの問題を試合後30日間振り返れます。未出題の問題・答えは他の参加者へ渡しません。
持込者が答えを知ることと、一般参加者に未出題内容を配信しないことも区別します。

部屋主は出題専任／回答兼任を選び、設定・ロビーに表示します。
専任は早押し・回答・勝敗に参加せず、「開始」「次の問題へ」を操作します。正誤判定は自動とし、手動判定・問題スキップは設けません。専任者の切断中は自動進行へ移ります。
兼任は他の回答者と一緒に遊べます。どちらも非レートです。
出題専任役は部屋主交代時に自動で引き継がず、次の試合前にロビーで選び直します。
部屋主の退室・切断時は、接続中の参加者から入室順に部屋主を自動交代します。元の部屋主が戻っても自動では戻しません。
ゲストにも既存の部屋の開始・設定・閉鎖を引き継げます。ただし、新しい部屋を作成する権限は得ません。
全員が退出すると10分後に部屋を閉じます。それまでに再入室すれば部屋を継続でき、空室による閉鎖の待ち時間を解除します。

開始・終端の保存と同時操作は[構成と復旧](../design/architecture.md)に従います。

## 人数の対応範囲

**部屋の回答者上限は8人です。** 出題専任者を加える場合は、回答者8人と専任者1人が参加できます。ロビー待機者も回答者枠に数え、追加の待機専用枠は設けません。総入室人数は回答者枠8人＋専任者1人までです。
16回答者は後続の任意拡張で、現在の必須範囲には含めません。以前の32人目標は対象外です。
現行コードのcatalog/config.ts・definition.ts・DBには2〜4人の制約があり、8回答者対応は未実装です。
対応時は設定・認可・DB制約・画面も揃え、同時早押し、保存サイズ、全接続配信、復帰、スマホの成績表示を検証します。
保存後ACK・重複排除・期限・非公開の条件を維持します。8回答者・専任者を含む負荷試験は未実施です。

## ゲスト・共有問題・カジュアル自動参加

ゲストは登録なしでカジュアル・部屋へ参加できます。管理者がカジュアル・部屋それぞれの受入を設定し、どちらも初期は禁止です。ランクは対象外。
サーバーが許可した範囲で部屋主が受入を選び、両方の画面設定と参加時の認可を一致させます。
部屋作成はログイン必須。未ログインには案内し、サーバーでもゲストの作成を拒否します。
ゲスト許可は作問資格の付与ではありません。
同じブラウザーのゲストは、同時に1つの対戦・待機先だけに参加できます。
同じブラウザーで30日間、自分の結果を確認し、出題済み問題を通報できます。Cookieを削除すると参照できなくなります。
後からアカウントを作成しても、ゲスト時の履歴は移しません。

通常問題を使う部屋では、部屋主がカテゴリ・難易度・共有元を選択します。初期は自インスタンスの利用可能問題すべてを対象にし、共有問題は明示的に選択します。
部屋では共有元ごとに問題を使う／使わないを選べます。Bの部屋でAを使い、Cを使わない設定が可能です。
共有元の許諾と受入側の設定を満たす利用可能問題だけを選びます。第三の所属元の参加者への許諾や共有範囲を拡張するものではありません。

部屋とは別に、非レートのカジュアル自動マッチングへの参加導線を設けます。運営による対戦機能の休止は[インスタンス運営](organization.md)に従います。
人数・ルール・ゲストの初期値はこのページの各項目に従います。
実装順と完了条件は機能別に整理しています。[機能別の計画](../development/plan.md)。
