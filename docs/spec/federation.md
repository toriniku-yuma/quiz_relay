# インスタンス間の連携

[ドキュメント一覧](../README.md)

**開催元が相手ごとの参加許可を決めます。所属元で未承認でも、開催元が許可すればURLから参加できます。**

## 許可と権限

参加はランク／カジュアルマッチを分け、「カジュアルマッチだけ可」にできます。
開催元の外部参加方式は「承認済みの組織だけ許可」と「禁止した組織以外は許可」の2方式です。初期値は承認済みのみ。相手組織ごとにランク、カジュアル・部屋の許可を設定し、初期値は両方許可です。明示禁止は承認と受入方式より優先します。
外部参加は所属組織のアカウント単位で扱い、参加元インスタンスを選びません。所属元で開催先を承認していなくても、開催元の方式・組織別制限を満たせば参加できます。所属元の明示禁止と組織全体の個人処分も確認します。A→BとB→Aは独立し、片方向だけの運用もできます。
問題共有は初期状態でオフです。送出側と受入側の承認・共有許可が揃って初めて利用できます。外部参加を広く許可しても、問題共有を自動承認しません。結果の配送に個別の共有許可は設けず、本人の結果の受取りは参加記録に結び付けます。
公開部屋の「誰でも」も参加制限に従います。
開催元がレート管理・不正対策のため参加条件を設定できるようにします。

peerの追加・解除と問題共有の許可は管理者専用。モデレーターへ委任しません。
一括変更は管理者が選択した既存対象と項目だけに適用し、実行前に差分を表示します。相手側・未選択・将来追加先へ適用しません。対象ごとに成功・失敗を返します。
画面とサーバーの両方で制限します。個人処分は専用モデレーション権限、外部全体／特定所属元の包括受入は別設定です。
投稿後の問題利用・共有は運営が管理し、作問者本人に共有可否を選ばせません。

不正の自動検知や過去レートの自動取消は採用しません。レートは [開催元別の仕様](gameplay.md#specification-027) に従います。

## 外部インスタンスをお気に入りに追加する

利用者は「インスタンス一覧」で本人の外部のお気に入りを確認できます。新しい参加先は開催元のインスタンスURLを入力して開きます。「承認済みの接続先から探す」は必要なときだけ開きます。

1. 所属組織のアカウントでログインし、「インスタンス一覧」を開く。
2. 開催先の `https://worker.account.workers.dev/?instance=UUID`（または `/rank/`・`/casual/`・`/rooms/`）を入力する。トップURLは対象1件の組織・インスタンス名・参加できる対戦種別を表示し、そこから参加方法を選べる。
3. 対象の行で「お気に入りに追加」を選ぶ。本人の登録を保存し、切替メニューに表示する。
4. 解除するときは、登録済みの行で「お気に入りから外す」を選ぶ。

URLで確認した情報は一覧表示用に保存します。参加先を開くときは対象1件を再取得し、参加時も最新の許可を確認します。お気に入り追加だけで定期的な外部同期を増やしません。一覧は画面表示・毎分・画面への復帰時に自動取得し、承認済み一覧では接続先の切替時にも相手の情報を取得します。通常の手動再取得ボタンを置かず、失敗時だけ再試行を表示します。URLの入手・共有方法は今後のinfoページで案内します。

お気に入りは所属組織のアカウントごとに保存し、同じアカウントの別端末でも利用できます。同じ外部インスタンスへの再追加は重複登録にしません。管理者による接続先の承認・参加許可、外部組織での新規インスタンス作成、直接URLの閲覧・参加で自動追加しません。

お気に入りの登録は接続先の承認や参加許可を変更せず、対戦参加・参加枠予約・認証チケット発行も開始しません。開催先と対戦種別を選び、実際の参加時に開催元の組織別受入条件、所属元の明示禁止、本人認証・個人制限を確認します。未追加の先も、同じ認可を満たせば直接URLや一覧から通常利用できます。

所属元の明示禁止・開催元の停止・参加許可の取消等で利用できなくなった先は、最新情報を取得した時点で切替メニューから隠します。本人の登録は保持し、再び利用可能になれば表示します。利用不可になった登録も本人が一覧から解除できるようにします。追加・解除・お気に入りの切替・画面移動だけでは、現在の参加処理・自動待機・部屋ロビー・開始済み試合と接続を中断しません。管理者の接続先管理は本人のお気に入りと独立して維持します。

この入口と外部のお気に入り保存は実装済みです。検証範囲は[検証状況](../development/testing.md#d1-clerk)を参照してください。非ログイン時のゲスト参加導線は維持します。自組織内のお気に入りの仕様は[一覧とお気に入り](overview.md#インスタンス一覧とお気に入り)を参照してください。

## 別組織の対戦へ参加する

所属組織のアカウントで別組織の対戦へ参加できます。本人確認画面には表示名と所属組織を表示します。所属元のローカルインスタンスの作成・休止・削除は、新しい外部参加の条件にしません。参加先のルールと個人処分を適用します。
所属元の一覧・お気に入り・URL入力から開催先の種別リンクを開くと、開催先自身のアカウントで未ログインなら、リンク元で現在ログインしているアカウントを自動確認して外部ログインします。「普段使う組織」を推測しません。開催先URLをブラウザーへ直接入力しただけでは所属元を決めず、ゲストまたは開催先のログイン入口を表示します。
開催先では通常のランク・カジュアル・部屋画面と共通サイドバーを使い、表示名と所属組織を表示します。画面を開くだけでは待機列・参加枠に入りません。対戦参加・部屋作成・入室を押した時点で所属元の最新の本人確認と参加制限を検証します。部屋一覧・出題設定の閲覧は参加前に利用できます。
「この組織のアカウントでログイン・登録」は別の入口にし、開催先自身のアカウントを優先します。外部ログインだけで開催先のClerk会員を作りません。外部の本人は所属元originと不変actorIdで識別し、同じGoogleアカウントでも別の所属元アカウントを統合しません。
共通の「ログアウト」は今開いている組織のログイン・参加セッションを終了し、ゲストへ戻します。所属元のログインは保ちます。戻り先から自動ログイン用の所属元指定を除去するため、再読込しても勝手に外部ログインしません。もう一度所属元のリンクから開けば再ログインできます。
カジュアルマッチ参加が許可された外部ログインユーザーは、部屋作成の個人制限がなければ参加先で部屋も作れます。
参加許可の取消は新規参加・待機・次の試合へ適用し、開始済みの試合とその再接続は維持します。

## 問題共有の許可

問題共有は初期状態では許可しません。管理者が相手組織を承認し、共有元インスタンスの送信と、受け取り先インスタンスの受信を許可します。カテゴリごとの公開設定は設けません。
許可された組み合わせでは、共有元が公開・審査済みの問題を送信できます。受け取った共有問題は再共有しません。共有元の使用停止と共有許可の取消は、共有先の新規出題へ反映します。
作者が自作問題を別インスタンスへ通常投稿した場合、その投稿は共有問題とは別に投稿先の運営が管理します。元の共有を停止しても、別の通常投稿へ自動で停止を伝播しません。
本人が自作を出力・再利用できる方針は維持します。共有先の取り込み選択・部屋の出題選択とは別の制約です。

## 取り込みを設定する

| 項目 | 選ぶ内容 |
| --- | --- |
| 共有元・範囲 | インスタンスの全カテゴリ、または選択したカテゴリ |
| 取り込み先 | 既存カテゴリ、または新しい通常／取り込み専用カテゴリ |
| 元分類 | 元カテゴリをタグとして保持し、共有元も管理画面に表示 |
| 難易度 | 簡単・普通・難しいの3区分をそのまま受け取る |

管理者・作問管理担当が、受け取るカテゴリと保存先を指定します。新しいカテゴリの作成と送受信許可は管理者だけが操作します。
設定画面は「問題管理 → 共有問題」です。「受け取り元を追加」から、共有元・受け取る範囲・保存先を順に選びます。全カテゴリを選ぶと、今後共有元で追加されるカテゴリも受け取ります。カテゴリを選ぶ場合は、選択したカテゴリだけを受け取り、追加分を勝手に含めません。
1設定で、共有元の1つ以上のカテゴリを保存先の1カテゴリへ割り当てます。元A→先X、元B→先Yなら、同じ共有元で2設定を作ります。複数の共有元から同じ保存先へまとめることもできます。元カテゴリの変更・削除は定期更新で反映し、分類を変更したい場合は保存済み設定の「受け取る範囲・保存先を変更」を開きます。
取り込み専用カテゴリは複数作成できます。このインスタンスからの作問・通常のJSON取込・通常問題の移動を、画面とAPIの両方で禁止します。
同組織内にも適用します。元のカテゴリ構造をそのまま作る必要はありません。
出題分類には取り込み先カテゴリを使い、元カテゴリのタグは使いません。
同じ共有元のカテゴリを複数の設定で重複して受け取ることはできません。既存の設定を変更するか、重ならないカテゴリを選びます。

難易度は全インスタンスで簡単・普通・難しいに固定し、対応表や未対応区分への自動割り当ては設けません。未知の区分を受信した場合は取り込みを拒否します。開催先での実績による自動補正と管理者の固定値は、通常の同期では上書きしません。
カテゴリ候補と問題は少量ずつ自動更新します。通常の再取得・手動同期ボタンは置きません。画面では保存済みの候補を読み、画面操作のたびに相手APIへ問い合わせません。

## 検索・個別除外・解除

権限内で自作側の問題と共有問題を横断検索します。
本文・正答・読みの検索、カテゴリ・タグ・状態に加え、共有元・元カテゴリ・取り込み先で絞り込めます。
未出題問題・正答・管理用タグは一般ユーザーへ公開しません。

「全問題」で共有元や共有問題を絞り込み、通常問題と横断検索できます。各問題の操作から「出題から除外」「出題に戻す」を選びます。
自インスタンスの新規候補だけから外し、共有元・他の共有先・進行中・過去結果は変更しません。
自動重複判定・自動除外は行いません。

**再同期・共有元の更新・共有の再開後も、指定済みの除外を維持します。**
除外済み一覧から検索・確認・解除できますが、解除しても元の停止・非共有・共有解除・取得失敗等の利用条件は満たす必要があります。

共有元の不変系列IDに除外を結び付け、改訂で新questionIdになっても除外を引き継ぎます。

## 共有解除・取得失敗

共有解除や取得エラーがあれば、その共有元の問題を新しい試合に使いません。
キャッシュが残っていても取得失敗を無視して使うことはしません。待機中・進行中の試合は、待機部屋の作成時に固定した内容で続けます。

共有解除後の未使用キャッシュは30日で削除します。過去の試合で使った問題は、その試合の振り返り期限まで保持します。

## 結果と退会の連携

開催先の結果を所属元の本人履歴にも表示します。所属元で未承認の場合も、自分の署名付き参加予約に結び付いた対戦結果だけを受け取ります。参加予約に結び付かない結果は受け取りません。本人履歴は所属組織のアカウント単位で表示し、問題共有や他人の履歴の閲覧許可を広げません。
連携先へ接続できない間も保存済みの試合結果は表示し、問題の振り返りには「接続できないため表示できません」と案内します。通信が復旧し、閲覧権限と保存期限を満たしていれば再び参照できます。開催先のレート増減は表示しますが、所属元のレートには加算しません。
退会時は連携先にも匿名化を通知します。試合結果・レートの整合性を維持し、過去の表示名を匿名化します。
インスタンスの完全削除時は共有先にも利用停止を通知します。共有先の試合結果は残し、削除対象の問題の振り返りは閉じます。通常の共有解除で振り返り期限まで保持する扱いとは区別します。
結果の手動訂正・取消機能は設けません。保存データの矛盾は上書きせず隔離し、運営へ知らせます。
配送の署名・再送などは[通信設計](../design/protocol.md)で扱います。
