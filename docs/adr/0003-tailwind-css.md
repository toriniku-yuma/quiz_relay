# ADR 0003：Tailwind CSSの採用

日付：2026-09-07。状態：ユーザー承認済み、実装未検証。ADR 0001のCSS選定を更新する。

## 背景

Quiz Relayの画面は対戦、マッチング、ランキング、管理が中心で、現時点では複数アプリ向けの共通UIライブラリや複雑なスタイル管理基盤を必要としていない。ユーザーはReactの部品化で再利用し、冗長なコードや追加の仕組みを抑える方針を希望した。

## 決定

React + TypeScript + Tailwind CSSを採用する。初期企画のPanda CSSは採用しない。Viteとの公式連携を使用し、実際のパッケージ版は初期実装で固定する。

再利用はReactコンポーネント、共通の見た目はTailwindのテーマ、状態ごとの差は型付きpropsとクラスの対応表で扱う。作業時の詳細は[development.md](../development.md)に集約する。バリアント管理ライブラリや独自の汎用UI基盤を初期要件にしない。

`clsx`と`tailwind-merge`も必要に応じて追加する方針をユーザー承認済み。条件付きクラスの可読性改善には`clsx`、外部classNameによる既定スタイルの競合解消には`tailwind-merge`を使う。共通の`cn()`は組み合わせの再利用が必要になってから設ける。具体的な追加条件は[開発方針](../development.md)に従う。現時点でこれらの依存は追加しない。

## 理由と影響

このプロジェクトでは既知のUI要件をReactとTailwindで表現できると判断した。主要な設計・検証作業を対戦裁定、連合、障害復旧へ集中できる。コード削減量や速度は未測定で、性能改善を採用理由として保証しない。

長いクラス列のコピーを繰り返せばTailwindでも重複は増える。役割のある部品と共通値へ整理し、先回りした抽象化は増やさない。複雑なデザインシステムが必要になった場合は、その要件に対して改めて設計を検討する。

今回は実装前の文書変更のため、既存のCSSコードや依存関係の移行作業はない。
