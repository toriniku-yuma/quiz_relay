# ADR 0008：JSONによる設定編集とDBの有効版切替

- 日付：2026-09-14
- 状態：採用。ユーザーから設定のハードコード解消と、将来管理画面から変更できる構成を依頼。

## 決定

人数・ルール・問題セット参照をJSONへ集約し、設定反映CLIでDBの不変版を追加・再利用して有効プロファイルを切り替える。既存試合の版は変えない。接続監視・待機期限・運用上限は別のruntime JSONへ置き、再ビルド・再起動で反映する。正式参加時の正はDBの固定版。

JSONは標準の読込機能だけで扱え、将来の管理APIとPostgres JSONBにも同じ構造を渡せる。JSONCのコメントとYAMLの記述上の利点は今回小さく、追加パーサーは導入しない。Wranglerは公式ツールのJSONCを維持する。値の意味・上限・操作は [設定手順](../configuration.md) へ記載する。

ファイルを実行時の唯一の正にすると管理画面からの変更に配置操作が必要になる。DBだけを直接編集する方式では手元での設定管理と検証を行いにくい。このためJSONを編集入口、DBを稼働中の正とし、CLIで明示的に反映する。将来の管理画面は同じJSON構造の検証とDBの版切替を使用できる。

## 影響

通常の設定変更ではソース・SQL・版番号の編集が不要になる。同じ設定の再適用で版を増やさない。管理PATはCLIだけに保持し、readerの書込権限は追加しない。管理画面の認可・監査とUIは1Dで実装する。クラウドへの配置は別作業。7問先取・3回失格・30秒猶予は初期値として維持し、固定版で変更可能にする。
