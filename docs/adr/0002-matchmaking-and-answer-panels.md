# ADR 0002：自動マッチングとカタカナ選択式解答

日付：2026-09-07。状態：ユーザー回答を反映。Q16〜Q19の追加回答も反映。実装未検証。

## 背景

ユーザーがopen-questions.mdへ回答し、自由入力の初期提案に代わり文字選択パネル、管理者の手動開始に代わり自動マッチングを指定した。

## 決定

- 解答はカタカナを1文字ずつ選択し、引っ掛け候補を含める。
- マッチング完了後に自動開始し、開始後の新規参加を認めない。
- 開催元が接続中actorを1人以下と判定したら即無効とする。0人も対象、再接続猶予なし。
- 同点優勝者へ各1勝を付与し、順位番号は1,1,3方式とする。
- 所属認証はメールのマジックリンクとGoogle認証を提供する。
- 全文後10秒の無buzzは無得点終了、解答時間切れは誤答とする。
- 表示速度と判定表示時間は仮値から調整し、試合開始時に版を固定する。

## 影響

パネル用カタカナ読みとダミー候補を問題版に持たせる。現在パネルは本人限定で配信し、DOで入力位置・パネル・期限を永続化する。公開イベントから正答位置や全パネルを取得できないようにする。

マッチングに予約・認証・接続完了の区別が必要となる。既存のmatchId付きチケットとの接続はprotocol.mdに提案を記載した。無効終了は通常終了と分けて記録し、順位に加算しない。

## 追加回答と調整値

[Q16〜Q19](../open-questions.md)により、初期4択（正解1・ダミー3）、誤選択時点で誤答、解答全体10秒、接続中actorが1人以下なら猶予なしで無効、Google認証を採用する。

人数と時間等は調整可能にする。マッチング人数の初期値は指定がないため2人を仮置きし、MVPの設定範囲は2〜4人を提案する。実行時はDBの固定版を正とし、定数は新規設定の初期値に使う。旧試合や待機列へ遡及しない。切断検知の具体的な実装と設定上限は技術検証で確定する。
